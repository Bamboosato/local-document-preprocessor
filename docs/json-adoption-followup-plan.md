# 採用決定後の独立試作・追加検証計画

2026-10-26。[採用決定と対象範囲](json-adoption-decision.md)に従い、本体統合は保留。先に観点を固定し、合成fixtureと新規contextで逐次実行する。

## ケースに先立つ観点

致命: 未検証ソース公開、文字・辺の欠落、外部送信・保存。重大: ズーム操作不能、旧図復活、再試行による本文消失、更新での作業破壊。

|観点|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|全体表示・拡大縮小・リセット・図/ソース|未検証ソース、図だけの失敗|200ノード・全ラベル・199辺|再試行・クリア・結果切替|
|非機能|self CSP・静的Worker・オフライン|取得失敗、保存拒否、容量不足|ズーム下限/上限、狭幅|二世代更新・複数タブ・復帰|
|データ|本文・全ラベル・全辺を維持|古い応答・不正ソース・キャッシュ混入|制御文字・巨大図|本文検証→図失敗→図だけ再試行|
|UI|キーボード・ボタン名・状態通知|無効ボタン、読めないソース|320px、全体図と100%表示|フォーカスを維持し切替・再試行|

## ケース・前提・期待値

共通前提: `experiments/json-gates/`のビルド済み追加候補、専用ポート4188、CSP付き配信、合成fixture、新規ブラウザーcontext。ChromeとEdgeを一つずつ実行。fixture本文・Pointer・ファイル名をログへ出さず、ID・状態・寸法・時間・一致判定のみ保存する。

|ID / fixture|意図|手順・期待値|
|---|---|---|
|AD-01 / max-tree|全体表示と全量保持|200ノード図を表示し全体表示→拡大→縮小→100%へ。全ラベル・辺は不変、寸法が有限、全体表示で図が表示窓内に収まる|
|AD-02 / zoom-boundaries|操作不能や無限拡大を防ぐ|最小/最大倍率、空状態、狭幅を確認。限界で該当操作を無効化し、スクロールとリセットが使える|
|AD-03 / validated-source|未検証本文を公開しない|生成中・不正ソースではソース切替・出力不可。検証成功後だけ同一ソースを表示し、図/ソース切替で本文を変更しない|
|AD-04 / display-failure|図再試行で本文を破棄しない|検証後の描画故障→ソース表示→図を再試行。本文一致・出力許可を保持。クリア後は本文・図・操作を失効|
|AD-05 / keyboard|操作の到達性とフォーカス|TabとEnterで図/ソース・ズーム・再試行を操作。図領域とソースに名前があり、主要操作を見失わない。実読み上げ成功とは扱わない|
|AD-06 / cold-resource|資産失敗からの誤回復を防ぐ|検証資産失敗後は図再試行不可。復帰だけでは再実行せず、明示的な再生成・検証で回復|
|AD-07 / distribution|必要なライセンス証跡の欠落を防ぐ|試作のproduction依存の名前・版・ライセンス原文・NOTICE・取得元・integrityを配布物へ記録。欠落はbuild失敗。法的条件の最終確認と機械収集の成功を分ける|
|UP-01 / two-tabs|更新で作業中のタブを壊さない|二世代SWと2タブで旧版を保持。全タブ終了後に新版へ移り、旧自Cacheだけ削除。他用途Cache保持、入力非復元、取得済みオフライン再生成|
|UP-02 / asset-404|更新失敗で旧版を破壊しない|新世代の1資産を配信側で404にしinstall失敗を確認。旧版・検証済み本文保持、新部分Cache削除|
|UP-03 / quota-injection|容量不足時の失敗経路を確認|新SWでのみCache.addAllへQuotaExceededErrorを注入し、旧世代保持と部分Cache除去を確認。OS実容量の証明ではない|
|UP-04 / storage-injection|保存拒否時の失敗経路を確認|新SWでのみCache.open拒否を注入。旧版の出力保持と更新失敗を確認。OS権限操作の証明ではない|
|G02-M02 / maximum-files|PCで未測定だった最大入力と完了結果・図・WASMを組み合わせる|合成PDFでWASM初期化後、50 MiBのJSONを20件保持し部分配列から各約1 MiBの結果を生成、最大図を追加して段階CDP測定。明示置換後に解放を確認。Fileネイティブ領域・OS総量・真のピークを測ったとはしない|

既存PR-01～08はChrome/Edgeで回帰する。変更のない旧Blob/data方式の全件再実行は選ばない。製品E2E範囲は現行CIのfull選択に従い、ローカルまたはCIの1 worker実行で確認する。macOS/iOS関連は今回対象外で、ユーザーの後日確認として別管理する。

実スクリーンリーダー、実200%ページズーム、実インストール済みPWA、OSメモリ圧など実操作・OS環境が必要な部分は、自動検査成功で代用しない。今回の実施結果・未実施範囲・残件は別報告へ残す。

UP系はアプリと同じビルド済み静的資産を、ケースごとの独立したlocalhostオリジンから配信する。SWの世代識別と故障注入だけを変更し、入力を配信コードへ埋め込まない。Chrome/Edgeを逐次実行し、サーバー・contextは各ケースで破棄する。実ブラウザーのSW更新成功と、OSへインストールしたPWAの更新成功を区別する。
