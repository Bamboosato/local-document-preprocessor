# JSON 対象選択 UI の実装・検証計画

PR #19 マージ後の CUR-01 を対象とする。本体の選択設定を拡張するが、マージ・デプロイ、macOS/iOS、実機確認は行わない。

## 先に確認する観点

まず防ぐべき重大な不具合は、閲覧操作による対象変更、古い応答による誤った確定、対象外のデータ混入、到達不能な候補、詳細の抜粋を出力欠落と誤認すること。

|区分|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|開閉と単一選択を分離、対象の子孫を変換|不適合方式の理由と確定抑止|兄弟50/51、詳細10/11|対象変更、ページ移動、選択位置復元、取消・再表示|
|非機能|Worker 内で構造・適合性を確認|キャンセル・古い応答を無効化|表示300行、詳細10,000コードポイント|高速な連続操作と再読込、別ファイルへ切替|
|データ|入力順、数値字句、RFC 6901 を保持|不存在 pointer を拒否|空キー、/と~、同じ長い接頭辞、深さ128|配列とobject、適合→不適合→適合|
|UI|ラベル付きラジオ、全名と絶対pointer確認|読込失敗時に確定できない|長い表示は省略、字下げ最大64px|Tab/スクロールは選択不変、DOM更新後に選択位置へフォーカス|

## 実行方針

合成 fixture を使い初期状態を新規ページに固定する。純粋関数の単体検証でページ・仮想窓・抜粋境界とデータ忠実性を確認し、対象 E2E で操作から出力まで確認する。共通画面に影響するため既存 Chromium E2E も回帰確認し、JSON 対象ケースを Chrome/Edge で順番に実行する。同一端末で並列実行しない。

ログはケースID・件数・成否を中心とし、実文書・PII を使用しない。失敗時は fixture ID、再現操作、trace を根拠に実装・観点・データ・環境を切り分ける。実機/PWA 世代管理、最大負荷の通し検証と配布条件は CUR-02〜05 として残す。
