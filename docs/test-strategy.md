# テスト戦略

更新日: 2026-10-06

## 1. テスト観点（ケースより先に固定）

### 機能観点

- 形式判定、anydoc/PDFium WASM 遅延初期化、Markdown 変換、plain text 変換。
- 選択順の逐次処理、部分失敗後の継続、再選択時のキュー置き換え、キャンセル後の範囲再確定による再変換。
- プレビュー、コピー、ダウンロード、クリア。
- Markdown ダウンロード時だけの YAML frontmatter（`title` / `originalUpdatedAt`）付与。
- password、破損、画像のみ PDF、resource limit の分類通知。
- `success` / `partial` / `failed` の品質判定、原本照合、PDF/文字異常警告、failed の出力停止。
- Worker 内の構造検査、PDF ページ範囲、PowerPoint スライド範囲、Excel シート選択、全体のみ形式の制御。
- PDF／PowerPoint のページ区切りオプション、境界単位の逐次変換、Markdown の N-1 区切り、plain text の区切り除去。
- DOCX の明示改ページ検出、既定オン、マーカー保存数の検証と不一致時の安全停止。
- production のみの SW 登録、manifest / アイコン、静的資産キャッシュ。開発時の非登録、登録失敗時のオンライン経路。

### 非機能観点

- 文書・結果・履歴・設定の外部送信・ストレージ保存がないこと、外部参照を取得しないこと。PWA の静的資産キャッシュは許可対象として分ける。
- PWA キャッシュは同一オリジン・クエリなし GET の許可 URL のみであること。非 GET、クエリ付き、外部 URL、文書本文を保存しないこと。
- オンライン初回／取得済み資産のオフライン／未取得 WASM／キャッシュ消去／旧版更新を区別し、SW install・activate・取得の非同期完了と競合を確認すること。
- UI 応答性、Worker/WASM のメモリ解放、連続キャンセル後の回復。
- 構造検査と変換の両方が Worker 内で実行され、複数ファイルの検査・変換が競合しないこと。
- ページ区切りオンでも同一文書内の単位変換を並列化せず、順序とキャンセル境界を維持すること。
- 大容量、低メモリ、低速端末、バックグラウンド復帰、ネットワーク断。
- Chrome / Edge / macOS Safari / iPhone Safari の差異。
- 静的ホスティング、CSP、WASM MIME、サブパス配信差異。

### データ観点

- 日本語、半角カタカナ、サロゲートペア、結合文字、改行コード、タブ。
- 氏名・住所・メール・電話・社員番号等の PII 相当文字列の完全一致。
- Type0 フォント、`UniJIS-UCS2-H/HW-H`、ToUnicode 欠落、構造不整合、機械可読、画像のみ、テキスト/画像混在 PDF。
- `U+FFFD`、C0/C1 制御文字、CJK 部首補助、非文字、孤立サロゲート、文字頻度差、空ページ。
- 空、極小、上限直下、上限一致、上限超過、圧縮爆弾相当。
- 表、結合セル、箇条書き、脚注、リンク、画像 alt、raw HTML。
- 元ファイル名（拡張子・日本語・引用符を含む）と `File.lastModified` の ISO 8601 変換。
- 拡張子不一致、署名なし CSV、壊れたコンテナ、暗号化文書。
- 1/最終ページ、単一ページ、中間範囲、全範囲、スライド順、Unicode/長い/非表示シート名、シート全解除。
- ページ区切りオン/オフ、0/1/複数境界、空ページ、先頭/末尾の不要な区切り、本文中の既存 horizontal rule。
- 選択範囲内外にそれぞれ固有文字列を置き、範囲外文字列が Markdown / plain text に 0 件であること。

### UI 観点

- 初見で「端末内処理」「文書と結果を保存しない」「OCR 非対応」「要原本照合」が分かる。PWA の資産キャッシュと区別した説明を README で確認する。
- キュー内の待機・変換中・成功・partial・失敗・キャンセルが識別できる。
- failed ではプレビュー・コピー・ダウンロードがなく、partial では警告と出力が併存する。
- 警告とエラーが色だけに依存せず、読み上げられる。
- キーボード操作、フォーカス、狭幅、長いファイル名、長文プレビュー。
- コピー成功/失敗、ダウンロード名、モバイル Safari の共有・ダウンロード挙動。
- Markdown ダウンロードだけに frontmatter が現れ、plain text、プレビュー、コピーには現れないこと。
- Vercel版相当の「変換範囲」「変更」要約、範囲ダイアログ、単位別文言、入力エラー、狭幅での操作性。
- PDF／PowerPointおよび明示改ページを検出した DOCX にページ区切り設定を表示し、既定オン、形式別説明文、変更後の未変換状態を色以外でも判別できること。

## 3. 最重要回帰

1. 機械可読 PDF の期待文字列をページ単位で原本と比較する。
2. `ICT本部品質技術ｿﾘｭｰｼｮﾝ部ｿﾘｭｰｼｮﾝ第一課` を完全一致で確認する。
3. Type0 + ToUnicode 欠落 PDF が「無警告の成功」にならないことを確認する。
4. `U+FFFD`、不審制御文字、極端な短文出力に追加警告が出ることを確認する。
5. C1 制御、CJK 部首補助、非文字、孤立サロゲートを不自然な Unicode として検出する。
6. PDFium の異常スコアが客観的に低い場合だけフォールバックし、`partial` にする。
7. 文字を推測置換せず、改善を保証できない場合は failed で出力操作を停止する。
8. 正常 PDF が `encoding_suspect` や `partial` にならないことを確認する。
9. 画像のみ、OCR 必須、テキスト/画像混在 PDF を別ケースとして確認する。

実 PDF が利用可能な場合は、fixture の合成だけで結論を出さず、対象ファイルをアプリ経路で再現して期待文字列を照合する。

## 4. 実行レイヤーと証跡

- Unit: plain text 規則、品質診断、エラー分類、キュー逐次性、Worker cancel。
- Unit: Markdown ダウンロード frontmatter のキー名、値のエスケープ、`lastModified` の ISO 8601 変換、plain text 非付与。
- Unit: OOXML 構造検査・選択再構成、範囲境界、XML entity、非表示シート、選択外混入 0 件。
- Unit: DOCX 本文の明示 `w:br type="page"` 検出、衝突しない一時マーカー、変換結果からのマーカー欠落時の安全停止。
- Component: 段落内改行と空行の表示、外部画像/リンクを生成しないプレビュー、状態・警告表示、Markdown/plain text ダウンロード境界。
- Browser integration: 実 anydoc/PDFium WASM で CSV、PDF範囲、PPTX範囲、XLSXシート、Type0 fixture を選択し、両出力、選択外混入 0 件、外部通信なしを確認。
- Browser integration: DOCX の明示改ページオン／オフを実 anydoc 経路で確認。PWA E2E は manifest / SW active / キャッシュ URL 制限を確認し、オフライン変換や実機インストールの証明にはしない。
- Artifact: `check:dist` で Worker の DOM-only / ストレージ API 混入、両 WASM、ライセンス、manifest / アイコン、SW の URL 制限を検査。文字列検査だけでデータ非保存を証明したとは扱わない。
- Fixture regression: 実文書またはライセンス上格納可能な最小 fixture で形式別に検証。
- Real device: Safari / iPhone Safari の Worker、WASM、メモリ、ダウンロードを確認。

失敗時はテスト名、ブラウザ/OS、入力 fixture の識別子、状態遷移、分類コード、スクリーンショット、trace を取得する。文書本文や PII を CI ログへ出さない。

## 5. 実行順序・依存・フレーク仮説

- Unit → build → browser integration → real device の順で原因切り分けを容易にする。
- Browser E2E は `workers: 1` とし、同一実機へ並列実行しない。
- 各 E2E は新しいブラウザ context で開始し、前テストの Worker/Blob URL/選択状態/SW/Cache に依存しない。キャッシュ検査は SW active を待つ。
- production preview の古いサーバー再利用を避けるため、未使用の `PLAYWRIGHT_PORT` を指定するか既存サーバーを停止する。
- 単体成功・通し失敗の仮説: WASM メモリ残留、キャンセル応答競合、ファイル順依存、Safari のメモリ圧迫、静的配信時の WASM MIME/CSP 差異。
- タイムアウト延長だけで解消せず、Worker 生成回数、要求 ID、画面状態を本文なしで記録して原因を分類する。

## 6. E2E 実行範囲の選定

範囲選択変更は構造検査、Worker通信、入力再構成、キュー状態、UIにまたがり、選択外本文の混入が致命リスクとなるため、PDF/PPTX/XLSX と Type0/画像分類の対象ケースを選ぶ。PWA 変更は静的キャッシュの許可境界を、DOCX 変更は実改ページ経路を、メタデータ変更はダウンロード限定の境界を対象とする。文書だけの変更では、主張の根拠となる既存ケースと成果物検査を選び、新規の製品実装テストは追加しない。全件を既定にはしない。Edge、Playwright WebKit、macOS Safari、iPhone Safari は別のリリース候補ゲートとする。

結果報告には必ず以下を明記する。

- 実施範囲と選定理由。
- 未実施のブラウザ・形式・実機と残存リスク。
- 失敗時の分類: テスト観点不足 / データ問題 / 環境問題 / 実装問題。

## 7. 優先度

CI では監査JSONの取得・構造・終了コード・集計の整合性をテストし、ゼロ件のみを許可する。E2E対象選定は文書のみ／個別機能／共通処理・依存／手動指定の境界と混在変更をテストする。検証観点とケースは [CI導入仕様](ci-configuration-proposal.md)、実行結果は [導入検証](ci-validation-report.md) に記録する。

- 致命: 文書データの外部送信・ストレージ保存、文書間または選択範囲外のデータ混入、無警告の重要文字欠落。
- 重大: キャンセル不能、UI フリーズ、誤った成功、password/画像 PDF/resource limit の誤分類。
- 軽微: 表示崩れ、文言、補助的なコピー通知。ただし操作不能・警告不可視は重大へ格上げする。
