## 判定基準と文書検査の観点

機能: 現行実装に必要な作業だけを残す。非機能: 旧方式専用の時間/CSP/更新条件を新方式へ要求しない。データ: 過去の成否・未証明事実・原文bytesを変更しない。UI/報告: クローズ理由を「成功」と混同させない。

正常系は旧専用項目の対象外クローズ、異常系は旧残件の無条件持越しや未検証のPASS化、境界は両方式に共通する本体要件、状態遷移は「旧未解消→方式変更により対象外」と「現行未完→現行証拠で受入」を分離する。最優先は誤った完了表示と、旧試作を完成させるためだけの不要な作業継続を防ぐこと。
