# JSON本体接続の現行残件と旧方式のクローズ

2026-10-30。ユーザー指示により旧方式固有の残件を整理した。現行方式は標準Mermaid＋JSON専用Workerによる本体接続。残件の現行管理は本書を正とし、旧報告の「残件」欄を現行の作業予定として取り込まない。[第一段階の報告](json-product-connection-validation.md)と[採用方針](json-adoption-decision.md)を参照。

## 判定基準と文書検査の観点

機能: 現行実装に必要な作業だけを残す。非機能: 旧方式専用の時間/CSP/更新条件を新方式へ要求しない。データ: 過去の成否・未証明事実・原文bytesを変更しない。UI/報告: クローズ理由を「成功」と混同させない。

正常系は旧専用項目の対象外クローズ、異常系は旧残件の無条件持越しや未検証のPASS化、境界は両方式に共通する本体要件、状態遷移は「旧未解消→方式変更により対象外」と「現行未完→現行証拠で受入」を分離する。最優先は誤った完了表示と、旧試作を完成させるためだけの不要な作業継続を防ぐこと。

## 旧方式固有: 方式変更により対象外（クローズ）

|ID|クローズする旧残件|理由・履歴|
|---|---|---|
|OLD-01|JSON木専用の独自SVG配置・折返し・外観改善、独立配置Workerの改良|標準Mermaid描画へ変更。旧layout-worker/diagram-worker-hostの完成を目指さない|
|OLD-02|図描画5秒・図初期化15秒の強制中断精度、iframe/配置Workerの隔離方式・旧ブラウザー別回避策|表示の時間保証を採用条件から解除。JSON解析/生成Workerと本体キューの取消はCUR-02で継続|
|OLD-03|独自図内ズーム・全体表示・100%リセット、旧倍率UI専用の実機確認|knowledge-board同等の図/ソース・スクロールへ変更。ブラウザー実200%倍率はCUR-05と区別|
|OLD-04|独自SVG/旧iframe専用の厳格CSP成立、Blob/data代替起動・配置資産のオフライン起動改善|現行本体CSPで標準図は検証済み。旧試作CSP再現のためだけの追加対応は不要。現行CSPを弱めない回帰確認は継続|
|OLD-05|旧独立SVG試作用のPWAパッケージ、旧ページ/Workerの同一オリジン二世代・Cache更新の完成|旧試作専用の配布物を新規整備しない。本体の実SW/全資産更新はCUR-03として別管理|
|OLD-06|旧表示方式だけの初期化/中断/オフライン不具合、過去キャンセル/フレークの個別原因追跡|旧結果は未解消/原因未確定の履歴を保持。現行実装/CIで再発し影響が確認された場合だけ、現行問題として起票する|

全項目の状態は**方式変更により対象外（クローズ）**。修正済み・検証成功・対応環境拡大を意味しない。旧ソース、テスト、証跡、失敗記録、原文を削除しない。今回はテスト/CI設定の削除や変更も行わない。旧SVG固有の実機確認をユーザーの待ち作業として残さない。

## ELK/WASM調査の扱い

[公開WASM調査](json-published-wasm-validation.md)のELK実checkout・anydoc完全再現・PDFium実リンクgraphの「未証明」は未証明のまま履歴へ保持する。これらを無条件に各独立タスクとして持ち越したり、すべての一意なビルド再現を一律の作業停止条件にしたりしない。

CUR-04で**現行バンドルに存在するもの**とその配布方法を確認し、必要な出典・提供物・告知を判定する。現行依存に必要な証跡が不足する場合だけ具体的な追加調査へ分解する。旧配置で使わなくなったからELK依存が消えたとも、原文収集済みだから配布承認済みとも判断しない。新たな対応証明や配布承認を今回得たわけではない。
