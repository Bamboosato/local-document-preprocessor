## 1. 目的

既存アプリの入力形式にJSONファイルを追加し、必要な範囲を読みやすいMarkdown／plain textへ変換できるようにする。APIレスポンス、設定、テスト結果などの構造化データを、資料やノートへ取り込みやすくする。

入力・結果・設定をサーバーへ送信せず、ブラウザのメモリだけで扱う既存の製品境界を維持する。

### 1.1 合意済みの方向

- 既存アプリの入力種類にJSONを追加する。
- Markdownの表形式とMermaidを選択できるようにする。
- 変換対象は「ファイル全体」または「一つの配列・オブジェクト」とする。
- 対象選択UIを重点設計する。展開と選択を分け、現在の対象と含まれる範囲を確認できるようにする。

### 1.2 今回採用する追加仕様と検証ゲート

2026-10-23のレビュー確認と更新指示を受け、v0.1で初版提案としていた次の内容を、今回の実装対象の基準として採用する。

- 出力スタイルを「項目表」「一覧表」「Mermaid構造図」の3種類とし、既定は項目表とする。
- UTF-8の単一JSON文書を扱う。ルートが単一値の場合もファイル全体として扱う。
- 数値の字句を保持し、重複キーを拒否する。
- Mermaidのソース生成・アプリ内の図表示・拡大縮小を今回の対象とする。本体への統合前に隔離表示の試作を検証する。
- リソース上限、一覧表の適用条件、キーボード操作、取消時の状態を本書のとおり定める。

採用範囲の決定と技術的な実現性の確認は別に扱う。依存ライブラリ・隔離方式は§13.1の検証ゲートで選定し、未測定の処理上限・性能は保証済みとしない。検証不成立の場合は本体への統合を止め、方式・上限・仕様の変更理由を両文書へ記録する。無通知で図表示を対象外にしたり、安全性・完全性の基準を緩めたりしない。

本書は[要件定義書v0.1](local-document-preprocessor-json-requirements-v0.1.md)の後継である。v0.1は履歴として保持し、JSON機能の実装基準には本書と画面設計書v0.2を用いる。

## 2. 調査した現行仕様と位置づけ

初版の調査基準は`543368e`、本版のレビュー・更新基準は[`f0eb983403cdea3514057ccc2c59a3ee6aa504c7`](https://github.com/Bamboosato/local-document-preprocessor/commit/f0eb983403cdea3514057ccc2c59a3ee6aa504c7)（2026-10-23に確認したmain）である。本書は追加機能の仕様であり、既存要件の全文置換ではない。

| 現行の確認事項 | 追加機能への適用 |
| --- | --- |
| 入力は最大20ファイル、各50 MiB以下 | JSONを含むキュー全体に同じ上限を適用 |
| Worker内で構造確認し、選択順に逐次変換 | JSONの解析・生成もWorker内。混在キューでも並列変換しない |
| 単一の検査対象では構造確認後に範囲ダイアログを表示。複数では各項目の「変更」から開く | JSONの範囲と出力スタイル設定を同じ導線に追加 |
| 範囲確定で旧結果を破棄し、待機状態へ戻す | JSONも同じ。設定中の仮変更だけでは破棄しない |
| Markdown／plain textのプレビュー、コピー、ダウンロード | 既存導線へJSONの結果を統合 |
| Markdownダウンロードだけにtitle／originalUpdatedAtを付与 | JSONでも継承。選択対象とスタイルは本文へ記載 |
| Markdown表は表示済み、Mermaid描画機能は未実装 | 表表示を再利用。安全なMermaid表示を追加 |
| 文書・結果・設定は永続化しない | ツリー展開、対象、スタイルもメモリだけで保持 |

根拠は末尾の「参照資料」に示す。anydocがJSONに対応することは前提にせず、JSON専用の決定的な変換経路を追加する。

## 3. 対象範囲

### 3.1 今回の対象

1. `.json`のファイル選択・ドロップ・構文検査。
2. JSONツリーの閲覧と、単一の変換対象の選択。
3. 項目表・一覧表・Mermaid構造図の生成。
4. 結果の表示・コピー・UTF-8ダウンロード。
5. 不正データ、処理上限、キャンセル、再設定、ファイル混在への対応。

### 3.2 対象外

JSONの編集・修復、JSON5／JSONC、NDJSON／JSON Lines、URLからの取得、貼り付け入力、JSONPath条件検索、キー単位の除外、複数対象の同時選択、行フィルター、任意の配列範囲、JSON内Markdownのレンダリング、スキーマ推定・検証、業務フロー／ER図／シーケンス図の推定、AI利用、図の画像書き出し、注釈保存、出力形式の自動変更。

## 4. 入力要件

| ID | 要件 |
| --- | --- |
| J-IN-01 | 拡張子`.json`を大文字小文字を区別せず受付。MIMEが空・text/plain・application/octet-streamでも拡張子と内容で判定する |
| J-IN-02 | UTF-8を厳密にデコードする。先頭のUTF-8 BOM一つは受理する。UTF-16／32と不正UTF-8は拒否し、文字コードの確認を案内する |
| J-IN-03 | RFC 8259に基づく単一JSON文書を解析する。前後のJSON空白は許可。空ファイル、コメント、末尾カンマ、複数文書、NaN／Infinity、余分な末尾文字は拒否する |
| J-IN-04 | ルートはobject／array／string／number／boolean／nullを受理する。ルート単一値の場合は「ファイル全体」だけ選択可能とする |
| J-IN-05 | 同一オブジェクト内の重複キーを文書全体で検出し拒否する。エスケープを復号したキー名で比較し、後勝ちで上書きしない |
| J-IN-06 | 数値は元のトークンを保持する。9007199254740993、-0、1.2300、1e400をNumber経由で丸めたりInfinityへ変換したりしない |
| J-IN-07 | 文字列・キーのコードポイント、配列順、オブジェクトの入力中のキー順を保持する。Unicode正規化をしない。JSON文字列のエスケープ表記自体の同一性は要求しない |
| J-IN-08 | 孤立サロゲートはアプリの対応範囲外として拒否する。正しいサロゲートペア、絵文字、半角カタカナ、エスケープされた改行・制御文字は値として保持する |
| J-IN-09 | 文書全体を検査してから部分選択を許可する。選択外に構文不正・重複キー・入力全体の上限超過があれば、部分選択で回避して成功扱いにしない |

数値字句とキー順・位置を保持できる構文木／トークンモデルを使用する。単純なJSON.parse→JSON.stringifyのみの構成ではJ-IN-05～07を満たさない。ライブラリの採否は依存監査・ライセンス・Worker対応を確認して決める。

## 5. 変換対象の選択

### 5.1 対象の定義

| ID | 要件 |
| --- | --- |
| J-SC-01 | 初期選択をファイル全体とする。通常操作では論理的な選択は1件で、未選択・複数選択を作らない。再解析等で旧Pointerが不整合になった場合は、そのPointerをエラーとして保持し、有効な選択済み対象とみなさず、利用者に選び直させる |
| J-SC-02 | ファイル全体に加え、文書中のobject／arrayを一つ選べる。配列の中のobject／array、空object／空arrayも対象とする |
| J-SC-03 | ネストしたstring／number／boolean／nullは閲覧のみで、個別対象として選択できない。ルート単一値は例外的にファイル全体で扱う |
| J-SC-04 | 選択した値自身と全子孫を変換する。兄弟・祖先のデータ値は出力しない。元の絶対パスは出所情報として出力する |
| J-SC-05 | 内部識別はファイルIDとRFC 6901のJSON Pointerで行う。ルートは空文字列。`/`は空キーを持つプロパティを意味し、ルートと混同しない |
| J-SC-06 | `/`を含むキーは`~1`、`~`は`~0`として扱う。ドット区切り、名称表示、配列の表示順から対象を再解決しない |
| J-SC-07 | 配列インデックスは0始まりで保持する。UIでは「1件目 [0]」と補助表示し、出力とJSON Pointerは元のインデックスを使う |
| J-SC-08 | 表示・本文のPointerは§6.4の可逆なJSON文字列リテラル表記を使う。表示表記を内部パスとしてそのまま解決しない |

### 5.2 操作要件

- 展開・折りたたみは矢印ボタン、選択はラジオボタンと項目名のラベル領域に分ける。矢印を押しても選択は変わらない。
- 初期表示はルートを展開、直下のコンテナーを折りたたむ。再度開いた場合は、そのファイルのメモリ上の表示位置を復元する。
- 選択を変えると対象名・型・件数・含まれる内容・JSON Pointerが即時に更新される。この操作ではまだ変換しない。
- 選択対象を含む親を折りたたんでも、別ページへ移動しても選択を保持する。固定表示の対象サマリーと「選択位置を表示」から現在地を確認できる。
- ツリーで省略表示した名称を、対象の識別キーに使用しない。空キー、長いキー、同名キー、数字だけのキーを区別する。
- 仮の対象・スタイルは「この設定に決定」でまとめて確定する。キャンセル・Escape・背景クリックは仮変更を破棄し、確定済み設定と旧結果を維持する。
- 単一ファイルの初回ダイアログを取り消した場合も、初期設定「全体／項目表」を維持する。
- 全体へ戻すときもルートのラジオボタンを使う。「全解除」は設けない。
- 再オープン時は表示位置を復元しても、仮設定は確定値から作り直す。復元位置が選択対象と離れていても選択を変えない。「選択位置を表示」は常に利用可能とし、再解析中のみ待機状態を示す。
- Tab／Shift+Tab、スクロール、表示窓の移動だけでは対象を変えない。選択済みラジオが未描画でもこの規則を守り、フォーカスのためだけに全ラジオをDOMへ作らない。実ブラウザで確認する。

## 6. 出力スタイル

### 6.1 適用条件

| ID／スタイル | 適用条件 | 既定・切替時の規則 |
| --- | --- | --- |
| J-OUT-01 項目表 | 対応するすべての値 | 初期値。JSONの構造と値を汎用的に表せる |
| J-OUT-02 一覧表 | 選択値が非空arrayで、各要素が一つ以上のキーを持つobject | キーの組合せが異なっていても可。未適用なら選択肢を無効化して理由を表示 |
| J-OUT-03 Mermaid構造図 | すべての値。ただし図の上限以内 | 親子関係をそのまま表す。意味や処理順を推定しない |

一覧表を選択中に対象をobjectなどへ変えた場合は、一覧表の指定を保持したまま適用不可理由を表示し、確定を無効化する。項目表への無通知の変更はしない。利用者がスタイルを選び直す。

### 6.2 項目表

列は「パス」「型」「値」とする。選択対象自身を先頭行に置き、深さ優先・入力順で全子孫を1ノード1行で出力する。

| 型 | 値の表現 |
| --- | --- |
| object | 直下プロパティ数。空の場合も0項目の行を残す |
| array | 要素数。空の場合も0件の行を残す |
| string | JSON文字列リテラル。空文字は`""`、改行は`\n`として区別する |
| number | 元の数値トークン |
| boolean／null | `true`／`false`／`null` |

パスは元ファイル内の絶対JSON PointerをJSON文字列リテラル化して表示する。ルート行は`""`とし、「ファイル全体（ルート）」を共通出所情報へ添える。選択範囲が途中からでも、元の階層・インデックスを取り違えない。

### 6.3 一覧表

- 配列の各objectを1行とし、先頭にシステム列「配列位置」を置く。行位置は元の0始まりインデックスとする。
- データ列は全要素に現れる直下キーの和集合。初出順で列を並べる。全キーが同じであることは要求しない。
- データ列の見出しはJSON文字列リテラルで表示し、システム列と空キー・同名キーを区別する。
- string／number／boolean／nullは項目表と同じ表現とする。object／arrayのセルはコンパクトなJSONとして全内容を保持する。数値は元トークン、キー順は入力順を保持する。
- キーが存在しないセルはシステム表記「（項目なし）」とする。`null`、空文字`""`、文字列`"（項目なし）"`と区別する。
- ネストを自動的に列へ展開せず、各レコードの直下キーだけを列にする。

### 6.4 Markdownの安全な文字表現

キー・値・パス・ファイル名はデータとしてエスケープする。パイプ、バックスラッシュ、バッククォート、改行、HTML区切り、リンク・画像の記法が表構造やコードフェンスを壊さないようにする。

文字列にMarkdownが含まれていても強調・画像・リンク等として解釈しない。JSONとしての文字列値は保持し、画面表現の省略やHTML除去によって出力値を失わないことを、生成MarkdownのASTと期待するセル文字列の比較で検証する。

#### Pointer・ファイル名の可逆表記

1. 内部PointerはRFC 6901の文字列のまま保持する。`~0`／`~1`の処理と、表示用エスケープを混同しない。
2. 画面の位置欄、項目表のパス列、共通出所情報の変換対象は、Pointer全体をJSON文字列リテラル化する。改行・タブ・制御文字、バックスラッシュ、引用符をJSONの規則で表し、U+2028／U+2029も可視のエスケープ表記にする。
3. Markdownへ入れる場合は、さらにMarkdownのセル・本文に適したエスケープを行う。JSON文字列化だけでMarkdown用エスケープを省略しない。画面はこの中間Markdownを実行せず、JSON文字列リテラル自体をテキストとして表示する。
4. plain textのパス欄は、Markdown解釈後のJSON文字列リテラルを維持する。区切り用のタブ・改行以外に、Pointer由来の生タブ・生改行を混入させない。
5. 画面・本文に出すファイル名と、階層を識別するキー名にも同じJSON文字列リテラル化の規則を用いる。親子の区切り文字と、キー内の区切り文字を区別する。

次表はMarkdown用エスケープを適用した後に読めるべき表記の例であり、内部文字列を直接記載する例ではない。

| 対象 | 表示・plain textで保持するJSON文字列リテラル |
| --- | --- |
| ファイル全体のPointer | `""` |
| 空キーのPointer | `"/"` |
| 通常のPointer | `"/results/0"` |
| キー内に実際の改行がある | `"/a\nb"` |
| キー内にバックスラッシュとnの2文字がある | `"/a\\nb"` |
| キー内に実際のタブがある | `"/a\tb"` |
| キー内にバックスラッシュとtの2文字がある | `"/a\\tb"` |
| スラッシュを含むキーa/bのPointer | `"/a~1b"` |
| チルダを含むキーa~bのPointer | `"/a~0b"` |

検証では、Markdown ASTのセル文字列が期待するJSON文字列リテラルと一致し、それをJSONとして復号して元のPointerへ戻せ、同じ値を解決できることを確認する。plain textでも生の列区切り数が増えず、上記の組合せを区別できることを確認する。

### 6.5 Mermaid構造図

- `flowchart TD`の構造図を生成する。JSONの各値を1ノード、親子関係を1エッジとする。選択対象を図のルートとする。
- コンテナーには型・直下件数、子にはキー名または配列インデックス、単一値には型・値を表示する。キー・値の並びは入力順とする。
- ノードIDは生成した`n0`等の安全な連番とし、入力値・キー名をIDとして使わない。
- 入力文字列をMermaid構文・リンク・HTML・設定・クリック命令として解釈しない。引用符、記号、改行、`end`、コードフェンス相当文字列などを安全にデータ化する。
- 全ノードと値を表現できるときだけ生成する。長い値を黙って短縮した図を完全な結果として出力しない。上限に達したら対象を小さくするか表形式に変更するよう案内する。
- Markdown本文にmermaidコードブロックを出力し、アプリでは図とソースを切り替えて確認できるようにする。
- 外部環境での図表示は、そのMarkdown閲覧環境のMermaid対応に依存する。出力に画像を埋め込まない。

ラベル上限の判定対象は、キー／配列位置・型・件数・値・区切り・引用符をすべて含む、最終的な表示テキスト全体とする。値やキーをJSONリテラル化した後、Mermaid構文用エスケープを施す前の文字列をUnicodeコードポイント数で数える。可視の`\n`は2、結合文字・ZWJを含む絵文字はそれぞれのコードポイントを数え、見た目の字数やUTF-16のlengthと混同しない。

コード部上限は、エスケープとLF改行への統一後、先頭のflowchart宣言から末尾のLF一つまでの、フェンス内文字列全体を数える。空白・改行・エスケープ構文は含み、外側のコードフェンス・出所情報は含まない。Markdown本文の10 MiB上限は別に確認する。設定画面の適用判定と最終生成で同じラベル生成・長さ検査を使い、設定時は値の先頭だけから長さを推定しない。

### 6.6 共通の本文・メタデータ

出力本文の先頭に「元ファイル」「変換対象」「出力スタイル」を記載する。ファイル名・絶対JSON Pointerは§6.4の可逆表記とし、全体ならPointer`""`に「ファイル全体（ルート）」を添える。選択範囲外のデータ値は記載しない。ファイル名とパスのキー名は明示的な出所情報である。

Markdownダウンロード時だけ、既存と同じ`title`と`originalUpdatedAt`のYAML frontmatterを追加する。本文には実行日時を自動付与せず、同一ファイル情報・対象・スタイルから同一出力を生成する。

plain textは生成したMarkdownから決定的に導出する。表は既存のタブ区切り規則を継承し、Mermaidは図のソース文字列を出力する。図の画像や自然言語説明へ置き換えない。frontmatterはMarkdownのプレビュー・コピー・plain textへ追加しない。

## 7. 出力例

入力ファイル`test-results.json`:

```json
{
  "generatedAt": "2026-10-22",
  "results": [
    {"id": "T001", "name": "ログイン", "status": "OK"},
    {"id": "T002", "name": "検索", "status": "NG"}
  ]
}
```

### 7.1 `/results`を一覧表にする場合

元ファイル: "test-results.json"\
変換対象: "/results"\
出力スタイル: 一覧表

| 配列位置 | "id" | "name" | "status" |
| --- | --- | --- | --- |
| 0 | "T001" | "ログイン" | "OK" |
| 1 | "T002" | "検索" | "NG" |

`generatedAt`の値は本文へ含めない。

### 7.2 `/results/0`を項目表にする場合

| パス | 型 | 値 |
| --- | --- | --- |
| "/results/0" | object | 3項目 |
| "/results/0/id" | string | "T001" |
| "/results/0/name" | string | "ログイン" |
| "/results/0/status" | string | "OK" |

上記は表本体の例。実際は共通の出所情報も付ける。

## 8. 状態・キュー・再設定

| ID | 要件 |
| --- | --- |
| J-ST-01 | 構造確認完了で初期設定「全体／項目表」を確定済み設定として持ち、適用可能なら待機状態にする。出力上限等で不可なら解析情報を保持した設定エラーとし、「変更」で部分選択等へ回復できるようにする。JSON／既存形式の混在を許可する |
| J-ST-02 | 全項目の構造確認が終了し、設定ダイアログが閉じるまで変換開始を無効にする。解析失敗項目はほかの正常項目の実行を妨げない |
| J-ST-03 | ダイアログ内の選択・スタイルを仮設定とする。確定時だけキュー項目へ反映して旧結果・旧エラーを破棄し、待機状態へ戻す。同一設定の再確定も既存と同じ再変換導線とする |
| J-ST-04 | 変換中は設定変更を不可とする。キャンセルは実行中・待機中だけを取り消し、完了済みの結果を維持する |
| J-ST-05 | 再選択はキュー・結果・ツリー状態を置き換える。ファイルID、構造検査世代、変換実行ID、設定版を照合し、古い解析・対象詳細・図描画結果を採用しない |
| J-ST-06 | 存在しないパスや単一値への部分選択は変換前に拒否する。別ファイルへ同名パスを転用しない。設定異常を全体選択へ黙って戻さない |
| J-ST-07 | ファイル別の対象・スタイルを独立保持する。別項目の変更・取消・失敗で設定や結果を混入させない |

### 8.1 Worker・解析キャッシュ消失時の回復

| ID | 回復契約 |
| --- | --- |
| J-RC-01 | 元File、一意なファイルID、確定Pointer・スタイル・設定版、最小限の検査サマリー、完了済み結果をUI側で保持する。解析木の存在を「変更」ボタンの利用条件にしない |
| J-RC-02 | Worker再生成時にWorker世代を増やし、そのWorkerにあった全JSON解析木を無効とする。キャッシュ追い出しも解析木なしとして同じ回復経路に入れる |
| J-RC-03 | 設定・詳細取得・変換に必要な解析木がなければ、その元Fileを必要時に逐次再解析する。全ファイルを自動で先読みし直さず、中断済みキューを自動再開しない |
| J-RC-04 | 再解析ではファイル別の解析世代を増やす。確定Pointer・スタイルを再検査するが、設定版は再解析だけでは変更しない。設定版の更新と旧結果の破棄は利用者の設定確定時に限る |
| J-RC-05 | 全要求・応答をファイルID、検査世代、Worker世代、解析世代、対象Pointer、設定版、要求IDの該当組合せで照合する。古い応答を最新要求へ採用しない |
| J-RC-06 | 回復中は「JSONを再読込中」とし、対象操作・出力設定の確定を停止する。取消は利用可能。再解析の取消・失敗・キャッシュ破棄だけで、確定設定・完了済み結果・既存キューの完了状態を上書きしない |
| J-RC-07 | 再解析失敗は再読込エラーとして理由と再試行を表示する。有効なPointerがない場合は対象不整合として確定を停止し、利用者に選び直させる。全体へ黙って戻さない。解析そのものが失敗した場合は入力再選択も案内する |

画面の業務状態（待機・成功・キャンセル等）と解析状態（保持中・未保持・再読込中・再読込失敗）を別に管理する。再読込失敗が現在の変換を妨げる場合は実行対象外とし、ほかの正常項目の実行は可能とする。以前の完了済み結果は当時の確定設定の結果として利用できる。

回復の代表例は、JSON Aの変換を完了し、続くPDF BをキャンセルしてWorkerが再生成された後、Aと未処理JSON Cの設定を開き直す操作とする。Aの結果を維持したままA／Cをそれぞれ必要時に再解析できることを検証する。Worker異常による再生成も同じ契約を用いる。

## 9. 品質判定と表示失敗

最優先で防ぐ不具合は、誤った範囲の変換、数値の丸め、子孫やキーの無警告欠落、文書間混入、危険な文字列の実行である。

- JSONには専用の品質診断を設ける。PDF用の抽出比較や文書抽出の「短すぎる出力」を、そのまま空JSON・単一値へ適用しない。
- 項目表は対象ノード数・全パス・型・値、一覧表は全レコード・キー和集合・セル、Mermaidは全ノード・エッジ・ラベルの対応を検査する。ノード数一致だけを完全性の証明にしない。
- 有効なJSONと選択範囲を規則どおり全量変換できた結果を`success`とする。既存の「変換成功（要原本照合）」を継承する。
- 利用者が明示した部分選択は欠落ではないため、それだけで`partial`にしない。画面と出力本文に対象を明示する。
- JSONでは自動修復・近似値・打ち切り結果を出力しない。構文不正・生成検証不一致・出力上限超過は`failed`とし、プレビュー・コピー・ダウンロードを停止する。
- 画面内のツリー・表のページ分け、詳細の抜粋は表示上の制御であり、生成本文とは別に扱う。件数と抜粋であることを明示する。
- Mermaid構文検証の失敗は変換失敗。検証済みMarkdownの図描画だけがレイアウト・タイムアウト等で失敗した場合は、図表示だけを停止し、明示的にソースへ切り替える。生成済みの検証済みMarkdown／plain textは利用可能とする。

## 10. リソース・性能

下表のJSON専用値はv0.2で採用する初期上限。境界一致を許可し、超過時は事前検査または生成処理で明示停止する。実機で成立することは§13.1の検証ゲートで確認し、変更する場合は両文書と試験期待値を一緒に更新する。

| 対象 | 上限／規則 | 超過時 |
| --- | --- | --- |
| 入力ファイル | 50 MiB／ファイル、1回20ファイル。既存と共通 | 既存の超過通知 |
| JSON全体の深さ | 128。ルート深さ0、値の親子関係ごとに+1 | 解析失敗 |
| JSON全体のノード数 | 100,000。コンテナーと単一値を各1。キー文字列は別ノードに数えない | 解析失敗 |
| 生成Markdown本文 | UTF-8で10 MiB。frontmatterを含めない | 現設定で変換不可。対象の縮小を案内 |
| 項目表 | 10,000データ行 | 同上 |
| 一覧表 | 10,000データ行、データ列100。システム列を除く | 同上。無通知で列・行を削らない |
| Mermaid | 200ノード、表示ラベル全体200コードポイント、最終フェンス内コード50,000コードポイント。数え方は§6.5 | 図形式を不可とし、対象・スタイルの変更を案内 |
| ツリーの直下表示 | 1階層につき50項目／ページ | ページ切替。全件を選択可能にする |
| ツリーの総表示行数 | 同時描画は300行まで。論理的な展開状態・全選択可能ノードとは独立 | 表示窓の移動／仮想化等。選択を解除せず、全行へ移動可能とする |
| ツリーの字下げ | 1階層16px、最大64px。深さは別の表示で補う | 深さ5以上も幅を追加消費せず、階層位置を確認可能とする |
| 選択内容サマリー | 直下10項目／ページ | ページ切替と表示件数を明示 |
| JSON詳細プレビュー | 先頭10,000コードポイント | 抜粋を明示。生成本文は切らない |
| 結果の表プレビュー | 100行／ページ。全列は横スクロールで確認 | 表示件数／総件数、出力は全件と明示 |
| 図資産の取得・初期化 | 15秒。描画5秒とは別に計測 | 該当コンテキストを破棄し、理由と明示的な再試行を案内 |
| 図表示の待機時間 | 5秒 | 図表示を中断しソース表示へ。キューを停止しない |

解析・走査・生成・構文検証はUIを長時間占有しない経路で行う。全構文木をUIへ毎回複製せず、必要なツリーページ・対象詳細を取得する。図レンダラーは破棄できる隔離コンテキスト等で実行し、タイムアウトと破棄の実効性を確認する。

### 10.1 解析情報全体の保持予算

| 保持対象 | 上限・破棄規則 |
| --- | --- |
| 完全なJSON解析セット | アプリ全体で原則1ファイル分。元バッファ、復号文字列、解析木、位置インデックスを一組とする。UI側に完全な複製を置かない |
| 同時の解析・変換用入力 | 一度に1ファイル。別ファイルの処理開始前に前の不要な解析セットと中間バッファを解放する |
| ファイル別メタデータ | 最大20件の元File参照、ID、ルート型、ノード数等の小さなサマリー、確定設定。全パス・全値・全表示行をサマリー名目で保持しない |
| 表示用情報 | 現在の表示窓300行、詳細先頭10,000コードポイント等、前表の範囲。不要なページ・旧応答は破棄する |

この一組に既存の50 MiB／100,000ノード／深さ128の上限を適用する。別ファイルへ切り替えると解析木を追い出し、必要になったら§8.1で再構築する。逐次事前検査で受け付けた20ファイルの解析木を蓄積しない。

数値・文字列を構文木・サマリー・表示要求のたびに全文複製しない。詳細の抜粋は走査・シリアライズ中に必要量へ達した時点で止め、全文生成後に切り出す方式を避ける。表示窓を除く全ラジオ・全ラベルの事前生成も行わない。

これらはアプリが保持する解析情報の予算であり、JavaScriptヒープの実使用量をバイト単位で保証するものではない。§13.1 G-02で復号文字列・一時コピー・完了済みMarkdown／plain text・図資産も含むピークと解放後の傾向を測定する。解析キャッシュを捨てるために既存の完了済み結果を黙って削除しない。受付上限と、全入力を同時展開できる保証を分ける。

巨大な単一文字列など、解析には成功しても全スタイルが不可で部分選択もできない入力には、「入力を分割・縮小して再選択」を案内する。利用できる小さいコンテナーがないのに対象縮小だけを案内し続けない。

### 10.2 ツリー表示位置への移動

総描画上限・字下げ上限は表示だけに適用し、変換範囲・選択候補からノードを除外する理由にしない。仮想化／表示窓の具体方式はG-03で決め、全ノードへの移動・キーボード操作・読み上げを満たす方式を採用する。

「選択位置を表示」の完了条件は、解析木が利用可能、必要な祖先・ページ・表示窓が対象を含む、ラジオが実DOM上で描画済み、画面内にスクロール済み、対象ラジオへフォーカス済みであること。完了前に移動成功を通知しない。途中で取消・別対象への変更・Worker再生成が起きたら旧移動要求を取り消す。

入力解析・変換の中止は既存Worker破棄方式に統合する。図表示の中止とは区別する。対応実機で、操作フィードバックが300 ms以内、キャンセルからUI操作可能状態への復帰が1秒以内であることを目標として測定する。未測定の性能保証として公表しない。

## 12. エラー通知

UIへ表示するエラーは分類・行列等の位置・上限値までとし、原文の抜粋、キー名、スタック、ローカルパスを含めない。新規内部コードの命名は実装時に既存エラー契約と整合させる。

| 状況 | 表示文例 | 利用者の回復操作 |
| --- | --- | --- |
| 不正UTF-8／未対応文字コード | UTF-8のJSONファイルを選択してください。 | 文字コードを変更したファイルを再選択 |
| 構文不正 | JSONの構文を確認してください（行N、列M）。 | 修正後に再選択。位置は1始まり、UTF-16コード単位で数える |
| 重複キー | 同じオブジェクト内に重複した項目名があります。 | ファイルを修正して再選択 |
| 孤立サロゲート | 対応できないUnicode文字表現が含まれています。 | ファイルの文字表現を確認 |
| 解析上限 | JSONの階層または項目数が処理上限を超えています。 | 入力を分割して再選択 |
| 一覧表の条件不成立 | 一覧表は、項目を持つオブジェクトが並ぶ配列で利用できます。 | 項目表／構造図を選択 |
| 対象不整合 | 選択した範囲を確認できません。設定を開き直してください。 | 対象を再選択 |
| 出力上限 | 選択した範囲は、この出力スタイルの上限を超えています。 | 対象の縮小・スタイル変更 |
| 生成検証失敗 | 変換結果を検証できませんでした。出力を停止しました。 | 再設定または再選択 |
| 図描画だけ失敗 | 図を表示できませんでした。Mermaidソースを表示します。 | ソース確認・コピー／ダウンロード |
| 再解析中／失敗 | JSONを再読込中／JSONを再読込できませんでした。 | 取消・再読込・入力再選択。確定設定と旧結果は保持 |
| 全スタイル不可・小さい対象なし | この入力を出力できません。入力を分割・縮小して再選択してください。 | 入力の縮小。使用できない対象選択を繰り返し案内しない |
| 図資産の取得・初期化失敗 | 図の表示に必要なデータを読み込めませんでした。 | 再試行。検証済みソースがある場合だけソース利用可 |

出力上限は設定時に判定可能な分を表示し、生成時にも最終確認する。判定待ち・エラー中は確定不可とする。

### 13.1 本体統合前の検証ゲート

以下は今後の実装に対するゲートであり、本版の文書更新で試作・性能試験が完了したことを意味しない。

| ID | 検証内容 | 通過条件・残す記録 |
| --- | --- | --- |
| G-01 | JSONの厳密解析・数値字句・重複キー・Pointerの可逆表記・3スタイルの小さな生成試作 | 合成入力と期待するノード／セルの照合、Markdown→plain textでも制御文字の区別と数値精度を保持。採用版・ライセンス・依存監査を記録 |

| G-03 | ツリー総300行・字下げ64px、深さ128、非表示の選択ラジオ、取消後の再オープン | 全ノード到達可能、Tabで選択不変、移動完了後に正しいラジオへフォーカス。Chrome／Edge／Safari／iPhoneと読み上げで方式を確認 |
| G-04 | 固定したMermaid版・ローカル資産・隔離描画の試作 | 危険文字列の不実行、外部通信なし、HTML・リンク等のないSVG、資産取得失敗、描画失敗、実効的な中断と再試行、古い描画の排除、PWA／Safariを確認 |

G-04は、iframeや設定名だけで独立中断を保証したとしない。親UIが応答でき、5秒の描画タイムアウトで隔離コンテキストを実際に破棄できることを、長時間描画の合成例で確認する。キャンセル・クリア・結果変更後の旧描画を採用しない。

図資産の取得・初期化には15秒の別タイムアウトを設け、描画5秒は初期化済みの隔離表示へ要求を渡した時点から計測する。タイムアウト時は該当コンテキストを破棄し、再試行では新しい要求IDと新コンテキストを使う。既存キューを自動で再実行しない。

オフラインは「必要資産取得済み」と「未取得／キャッシュ消去」を分けて確認する。後者で図表示不能になる場合は理由と再試行を案内し、オンラインへ復帰してから明示操作で再試行する。生成と構文検証が済んだソースだけを出力可能とし、構文検証用の資産も未取得なら未検証ソースを成功扱いにしない。

## 14. テスト観点

リポジトリのAGENTS.mdに従い、テストケースを作る前に防ぐべき不具合と観点を整理する。

| 区分 | 正常系 | 異常系 | 境界値 | 状態遷移 |
| --- | --- | --- | --- | --- |
| 機能 | 全体／部分と3スタイル、混在キュー | 不正パス、対象とスタイルの不一致 | 空object／array、単一値、列の和集合 | 確定・取消・再確定・再選択・キャンセル |
| 非機能 | 外部通信なし・保存なし・逐次変換 | Worker／図表示失敗、初期化失敗 | 全処理上限の一致と+1 | 中止後の回復、古い応答排除 |
| データ | 日本語、半角カナ、精密数値、入力順 | 不正UTF-8、重複キー、孤立サロゲート | 空キー、長いキー、巨大値、null／欠損／空文字 | 別ファイル同名パス、配列内同名object |
| UI | 展開と選択の分離、対象の可視性 | 無効スタイルの理由、エラーと回復 | 320px、拡大200%、50／51項目、100／101行 | 折りたたみ中の選択保持、フォーカス復帰 |

レビュー補足の重点観点は、解析セット1件の追い出し・再構築、JSON A／PDF B／JSON Cの通し操作、長い文字列と総保持量、制御文字Pointerの復号と列区切り、表示ラベル199／200／201、コード部49,999／50,000／50,001、ツリー299／300／301行・深さ128、未描画ラジオのTab移動、図資産の取得失敗と取得済み／未取得オフラインとする。

ケースには前提・操作・期待結果・検出意図を明記する。本文を含む実データではなく合成fixtureを使用する。失敗証跡に秘密情報を含めない。

## 15. 受入条件

| ID | 条件・確認意図 |
| --- | --- |
| J-AC-01 | 正常なUTF-8／BOM付きJSON、ルート6種を受理し、空文書・不正文法等を拒否できる |
| J-AC-02 | 9007199254740993、-0、1.2300、1e400と日本語・半角カナが、3スタイルの生成物とplain textで規則どおり保持される |
| J-AC-03 | 重複キー（エスケープ等価を含む）を上書き前に検出し、出力できない |
| J-AC-04 | `/results`の変換結果に兄弟の固有値を含めず、全子孫・全キーを含む。空キー、`/`、`~`、数字キーを正しく識別できる |
| J-AC-05 | 展開・折りたたみ・ページ切替で選択が変化せず、選択位置へ戻れる。対象・件数・Pointerが一貫する |
| J-AC-06 | 取消は設定と旧結果を維持し、確定は設定を反映して旧結果を破棄する。再設定の途中で意図せず出力が失われない |
| J-AC-07 | 一覧表の異なるキーを持つレコード、ネスト、欠損／null／空文字を区別して変換し、不適合対象への切替では理由と確定不可を表示する |
| J-AC-08 | パイプ、改行、バッククォート、HTML、画像記法、リンク、Mermaid構文相当文字列が構造を壊したり実行されたりしない |
| J-AC-09 | 表・図の上限一致と+1、入力深さ・ノード数・サイズ上限を確認する。無警告の省略結果を出力しない |
| J-AC-10 | 複数ファイルの逐次処理・取消・再選択で文書間混入と古い応答採用がなく、完了済み結果を保持する |
| J-AC-11 | Markdown／plain textのコピー・ダウンロードに選択範囲とスタイルが正しく反映され、frontmatterの付与先が既存と一致する |
| J-AC-12 | Mermaidの図／ソース表示と図表示失敗時の回復を確認し、検証失敗結果は出力できない |
| J-AC-13 | 文書・設定・結果の永続化、本文のログ出力、外部通信、外部画像／リンクの生成がない |
| J-AC-14 | キーボードのみ・スクリーンリーダー・320px・200%拡大で主要操作を行え、取消／確定後のフォーカスが適切に復帰する |
| J-AC-15 | 既存のPDF／Office／CSVの変換・範囲・改ページ・品質表示・frontmatter・PWAに回帰がない |
| J-AC-16 | Worker再生成・解析キャッシュ追い出し後に必要時再解析でき、確定設定と完了済み結果を保持する。再解析失敗・取消・旧応答逆転でも範囲を勝手に変えない |
| J-AC-17 | 解析セットが全体で原則1件、入力の同時解析が1件、表示情報が上限内であり、20ファイル事前確認・連続切替で全解析木を蓄積しない。全スタイル不可の入力に分割・縮小を案内できる |
| J-AC-18 | 改行とバックスラッシュn、タブとバックスラッシュt、空キー、/、~のPointerが画面・Markdown AST・plain textで区別され、JSON復号後に元の値を解決できる |
| J-AC-19 | 表示ラベル全体と最終コード部の境界値を設定時・生成時の同じ規則で判定し、型等の付加や構文エスケープの増加を見落とさない |
| J-AC-20 | 表示行・字下げの上限下でも全対象へ到達し、非表示選択・再オープン時にTabだけで対象が変わらず、「選択位置を表示」の描画・スクロール・フォーカス完了を確認できる |
| J-AC-21 | G-01～G-04の記録があり、図の資産取得・初期化と描画のタイムアウト、失敗後再試行、古い図の排除、取得済み／未取得オフラインを区別して確認できる |

実装完了時にnpm run check、依存監査、文書整合性検査を行う。E2E範囲はAGENTS.mdとCI方針に基づき選ぶ。本変更は共通契約・Worker・描画依存に及ぶ見込みのため、共通経路を変更した場合は全E2Eを1 workerで実施する。対象限定にする場合は根拠と未実施リスクを記載する。

Chrome／Edge／macOS Safari／iPhone Safariを最終確認対象とし、実機未確認を単体試験だけで完了扱いにしない。性能・PWA更新・隔離図表示の確認結果を記録する。
