致命リスクは未検証本文の出力、古い設定/別文書の混入、JSON入力の実行/送信/永続化、数値や文字の無警告欠落。重大リスクは取消不能、旧結果の意図しない破棄、既存形式の失敗。

## 第一段階の成果と検査

生成coreと標準描画を製品配下の共通実装へ移し、独立試作も同じ実装を参照する。JSON専用client/Workerと既存WASM clientを形式分岐し、対象設定・3スタイル・逐次キュー・ResultCardへ接続する。対象UIは階層ごと最大300行のページ閲覧として先に接続し、既定の展開型仮想ツリー/詳細UIすべての完成とは扱わない。

- JC-01: 数値字句/制御文字/Pointer/3スタイルと不正JSON、選択外不正、生成上限。単体で生成adapterを検査。
- JC-02: clientの旧Worker/未知要求/取消/遅延File読込を合成Workerで検査。本文は失敗ログへ出さない。
- JC-03: 実JSON入力から設定・確定・変換・図/ソース・MD/TXTダウンロードを本体UIで検証。JSONだけのWASM要求0。
- JC-04: JSON A/既存CSV B/JSON Cの混在、不正データ後の継続、再設定/取消/全消去・再読込。別結果の保持を確認。
- JC-05: 標準描画の旧SM-01～08を共通化後も対象検査として実行。5秒強制中断は採用条件に戻さない。

ローカルE2Eは変更範囲の対象ケースをChrome/Edge headlessで逐次実行する。root既存全E2Eは本体キュー・依存変更の回帰としてChromiumで逐次実行し、同一実機の並列スクリプトは使わない。CIは既存selector。実機/PWA二世代更新/負荷/読み上げ/実200%ズーム/タッチは未実施。各結果に実施理由と未実施範囲を記録する。

初期状態は合成入力・新しいcontext・保存データなし。ログはケースID/件数/成否/ブラウザー版のみ。失敗時はfixture識別子・世代・原因カテゴリで切り分け、本文/個人パスを出さない。まず単体→対象UI→既存回帰→CIを順に実行し、原因を実装/データ/環境/観点不足に分ける。
