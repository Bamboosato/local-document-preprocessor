# JSON本体接続前の設計・独立検証計画

2026-10-27。基点はmain `e927fe1`（PR #16取り込み済み）。本体統合、macOS/iOS、マージ、デプロイは対象外。試作と報告書のレビュー用PRを作成する。

## ケースを作る前の観点

まず防ぐべき致命的不具合は、未検証出力の公開、別ファイルの結果混入、入力の送信・保存、無警告の文字欠落。重大な不具合は誤った成功表示、キャンセル後の復活、更新後の資産不整合、回復不能である。

|観点|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|既存PDF変換とJSON生成・図表示|不正JSON、資産欠落、WASM実行禁止|逐次キューの先頭/中間/末尾|成功→失敗→次へ、取消→遅延応答破棄|
|非機能|製品相当CSPでWASMと静的Worker共存|CSP違反、コールドオフライン、保存拒否|全実行資産をmanifest照合|温オフライン→新Worker、再読込で入力消去|
|データ|元本文とplain text、MDダウンロードのみfrontmatter|不正出力はコピー/DL不可|安全でないファイル名、固定更新時刻|再確定時のみ該当結果失効、他結果維持|
|UI|既存採用UIのラベルとフォーカス|図失敗時は検証済みソース|最大図・狭幅・倍率上下限は既存AD検証を継承|図層の再試行と変換状態を分離|

## 実行ケースと意図

新規の専用localhostオリジン、合成PDF/JSON、空のブラウザーcontextを使う。同一Windows実機ではChrome→Edgeの順に実行する。本文、ファイル名、Pointer、ローカルパスは証跡へ出さない。

|ID|意図と期待値|
|---|---|
|IC-01|製品の既存変換コードを使ったPDF（anydoc・PDFium両WASM）、静的JSON生成Worker、検証/配置Workerを同じCSPで実行。図の全ラベル/辺を照合し、外部通信・動的Worker・予期しないCSP違反がない|
|IC-02|既存`processSequentially`でPDF成功→不正JSON失敗→正常JSON成功。中間失敗が前後結果を壊さず、各結果がそのitemへだけ渡る|
|IC-03|既存逐次処理の実行途中で取消。完了済み結果を残し、遅延完了と後続開始を採用しない|
|IC-04|既存のplain text導出・MDダウンロード用frontmatter関数を使い、JSON出力契約と一致。未検証図は出力不可|
|IC-05|同じ世代の実行資産を先行取得後、温オフラインで再読込して新規Workerと両WASMを実行。入力は復元されず、保存先は静的allowlistのみ|
|IC-06|SWを使わない新contextでWASM取得を失敗させる。失敗を検出し、オンライン復帰だけでは再実行しない。利用者に相当する明示実行で回復|
|IC-07|WorkerレスポンスにもWASM実行を許さないCSPを返す負の対照。WASM変換が失敗する（有効な検査か確認）|
|IC-B01|生成manifestと実行ファイル全量・SHA-256が一致し、JS/WASMの脱落を検出。世代識別にCSPと全実行資産を含む|
|IC-L01|実バンドルに入る依存モジュールをroot/prototypeのlockと対応付け、原文/NOTICEと取得元を収集。未識別・証跡欠落は失敗|
|IU-01|今回のWASM込みビルドで二つの旧タブが新版を待機させ、最後の旧タブ終了後だけ新版へ移る。自分の旧Cacheだけ削除し、無関係なCacheは維持。入力は復元せず、新版で温オフラインの両WASMと図を再実行|
|IU-02～04|新版WASM実404、新SWへのCache容量例外/保存拒否注入でinstallが失敗。新版部分Cacheは削除し、旧版の検証済みソース・両WASMの実行を維持。実OS容量枯渇とは区別|

## 実施範囲と限界

E2Eは新しい独立試作の対象ケースをChrome/Edgeで実施する。本体ソースは変更しないため、本体E2E全件のローカル再実行は既定にしない。CIの既存選定規則は維持する。Windows実読み上げ、実200%ブラウザーズーム、タッチ、インストール済みPWA、実容量枯渇・OSメモリ圧は自動化の成功で代用しない。

配布条件は実バンドルと一次資料を照合する。ライセンス原文収集だけで対応ソース提供を完了と判断しない。新しい試作CSP/Cacheも製品全体の採用完了ではない。
