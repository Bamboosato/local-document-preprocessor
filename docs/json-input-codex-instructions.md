## 1. 目的と今回の着手範囲

既存アプリのINPUTにJSONを追加する。ファイル全体、または一つの配列・オブジェクトを選び、項目表・一覧表・Mermaid構造図のMarkdownとplain textへ変換できるようにする。

**最初のタスクは、既存試作を引き継いだ残件整理・追加検証・製品採用案の具体化とする。本体統合は、仕様上の検証ゲートと方式採用条件を満たすまで行わない。** 初回から全ゲートを未着手として作り直さず、既存結果と実行環境を確認して必要な追試を行う。

本書の後半には、本体統合へ進める条件が成立した後の実装指示も記載する。条件未成立の場合は、進められる試作・検証・設計を完了し、未解消事項を具体的な成果物として残す。本書を理由に、未確認項目を成功扱いにしたり、既存の本体統合保留を解除したりしない。

## 5. 実装時に必ず守る契約

### 5.1 入力・データ保持

- UTF-8の単一JSON文書を厳密に検査し、文書全体の不正・重複キーを部分選択で回避させない。JSONC／JSON5／NDJSONを受理しない。
- 数値は元トークンを保持する。`9007199254740993`、`-0`、`1.2300`、`1e400`をNumberへ変換して出力しない。キーの入力順、Unicode、空値を保持する。
- 内部PointerはRFC 6901、ルートは空文字列。画面・本文のPointerはJSON文字列リテラル化し、その後に出力文脈へエスケープする。実改行とバックスラッシュ+n、実タブとバックスラッシュ+tを区別する。
- 解析・生成は専用Worker経路とし、JSONだけの操作でanydoc／PDFium初期化を必要としない。
- 完全な解析セットはアプリ全体で原則1ファイル分。UIへ全木を複製せず、全パスや全値をメタデータ名目で蓄積しない。詳細の抜粋は必要量に達した時点で走査・生成を止める。

### 5.2 対象選択UI・状態管理

- 初期は「ファイル全体／項目表」。部分選択は一つのobject／array。展開と選択は別操作とする。
- 仮設定はダイアログ内で保持し、取消・Escape・背景クリックでは確定設定と旧結果を維持する。確定時だけ該当ファイルの旧結果を破棄し待機へ戻す。同一設定の再確定も許可する。
- ツリーは直下50項目／ページ、同時描画300行、字下げ最大64px。全ノードに到達可能とし、Tab・表示窓移動・ページ移動だけでは対象を変えない。
- 「選択位置を表示」は対象ラジオのDOM描画・スクロール・フォーカス完了後に成功とする。未描画の全ラジオを追加して回避しない。
- **追補1の確定条件:** `/results`＋一覧表→`/summary`＋一覧表→`/results`＋一覧表では、一覧表を保持する。現在の設定の適用判定・詳細取得中は確定不可、正常完了後はスタイル変更なしで確定可能。古い応答で有効化しない。
- ファイルID・検査世代・Worker世代・解析世代・Pointer・設定版・要求／実行IDの必要な組合せを照合する。同名ファイルや旧応答の混入を防ぐ。
- Worker破棄・キャッシュ追い出し時は元Fileから必要時に逐次再解析する。業務状態と解析状態を分け、再解析だけで設定版・完了結果を変更しない。中断キューを自動再開しない。

### 5.3 生成・品質・回復

- 項目表は選択値自身と全子孫を入力順の深さ優先で出力する。一覧表は条件を満たす配列の全行・直下キー和集合を初出順で出力する。構造図は構造を表し、業務上の意味を推定しない。
- ノード数だけでなく全パス・型・値、全セル、全ラベル・親子辺を照合する。表示の抜粋と全量の出力を分離する。
- 上限超過・生成検証不一致では切り詰めて成功にしない。利用可能な対象がない巨大単一値には入力の分割・縮小を案内する。
- **追補1の回復区分:** 検証済み本文がある場合の「図を再試行」は、新コンテキスト・新要求IDで図資産取得／初期化／描画だけを再実行し、本文・品質・キューを維持する。
- 有効な検証済み本文がない場合は出力を停止し、「変更→この設定に決定→変換開始」で生成・構文検証・品質判定を再実行する。「図を再試行」から未検証本文を公開しない。
- オンライン復帰だけで自動実行しない。再確定したファイルだけを待機へ戻す。ほかの待機項目は通常処理し、完了済み・失敗・取消項目を自動で再実行しない。

### 5.4 上限・安全性

上限と境界一致の扱いは要件定義§10、Mermaidの計数は§6.5を実装・試験の共通基準にする。設定時と生成時で異なる計数関数を作らない。

| 対象 | 採用済みの初期上限 |
| --- | --- |
| 入力 | 20ファイル、各50 MiB |
| JSON全体 | 深さ128（ルート0）、100,000ノード |
| Markdown本文 | UTF-8で10 MiB、frontmatterを除く |
| 項目表／一覧表 | 各10,000行。一覧表はデータ列100まで |
| Mermaid | 200ノード、各表示ラベル全体200コードポイント、最終フェンス内コード50,000コードポイント |
| 表示 | 詳細10,000コードポイント、サマリー10項目／ページ、結果表100行／ページ |
| 図 | 資産取得・初期化15秒、初期化後の描画5秒。独立中断と旧結果排除を確認 |

Mermaidラベルはキー・型・件数・値・区切り等を含む全体をJSONリテラル化した後、Mermaid構文用エスケープ前に数える。コードはLF正規化し、先頭宣言から末尾LF一つまでを数え、フェンスを除く。字形数・UTF-16 lengthと混同しない。

入力・結果・ファイル名・Pointer・設定を外部送信、ログ出力、永続化しない。Cache APIは静的資産だけに用いる。外部CDN、HTMLラベル、画像、リンク、click命令、入力由来設定を許可しない。SVG生成物と実通信を検査し、`__proto__`等も通常データとして扱う。既存プレビューの制限を維持する。

## 7. 実行する検証と記録

現在のpackage.json・CIを確認してコマンドを選ぶ。以下は本書作成時の例であり、異なる環境での成功を保証するものではない。

試作の準備・単体検査・ビルドは、rootの必要依存を準備した後、試作ディレクトリで順次実行する。

```sh
cd experiments/json-gates
npm ci --ignore-scripts
npm test
npm run build
```

実ブラウザー検証は試作READMEに従い、ビルド済みpreviewを起動して実行する。ブラウザー・実機検証は同一端末で並列実行しない。既存iframeの未達再現と独立Worker候補の検証を混同しない。利用できないブラウザーを無断で除外して全環境成功と表示しない。

本体統合時の基本確認はrootで順次実行する。

```sh
npm ci
npm run test:security
npm run audit:security
npm run check:docs
npm run check
```

依存はproduction・全依存とも現行の監査方針を維持し、脆弱性の例外登録・閾値緩和で通さない。新規依存は固定版、lockfile、採用理由、配布物のライセンス、Worker・CSP対応を確認する。

E2Eは現行CIの範囲選択に従う。依存・共通処理の変更で全件が選ばれる場合は全件を実施し、それ以外は対象範囲・理由を記録する。ローカルでの実行例は`npm run test:e2e -- --workers=1`。実機専用項目は別途確認し、単体・headlessの成功を代用にしない。

受入確認はJ-AC-01～23・UI-01～26へ対応付ける。特に追補のJ-AC-22／23・UI-25／26、JSON A完了→PDF B取消→A／C再設定、応答逆転、クリア後の旧図、取得済み／未取得オフラインを省かない。PDF／Office／CSV、Markdown／plain text、コピー・ダウンロードとfrontmatterの回帰も確認する。
