## 検証観点（実装・ケース作成前）

最優先は、構文未検証の本文を成功扱いすること、文書間混入、旧Worker/新表示の版不一致、必要な原文・表示の欠落を防ぐこと。

|観点|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|本体JSON選択→Tiny検証→図/ソース・コピー/保存|Tiny読込失敗・Worker異常時は出力しない|既存200ノード・50 KiB制御を維持|変更・取消・再試行と旧応答破棄|
|非機能|同一オリジンCSPでページとWorkerが同一Tinyを使用|欠落/改変材料はbuild・配布物検査で停止|PWA全静的資産のbytes/hash|旧タブ維持・更新失敗・新世代のオフライン回復|
|データ|全ラベル・親子辺、危険文字、原文68点と表示・パッチを保持|不要な通常版Mermaid/elkjsの配布、別版原文を拒否|数値字句・選択範囲・大入力|別ファイル/設定間で結果を流用しない|
|UI|既存第三者ライセンス導線から原文・由来・変更へ到達|描画だけ失敗しても検証済みソースは保存可能|狭幅・キーボードの既存制御|一覧→原文、ネットワーク遮断後も閲覧|

初期状態は合成fixtureと専用ブラウザーcontextを使用する。本体依存を切り替え、描画と構文検証を同時に接続してからbuild・配布物検査を行う。機能試験→ライセンス閲覧→PWA世代試験を逐次実施する。同じ実機への並列実行はしない。E2EはJSON、状態回復、PWA、混在キュー/実WASMの影響箇所を選定し、全件を既定にしない。実配信・実機はローカル成功で完了扱いしない。

## 接続設計

TinyのIIFEは改変せず、ViteのURL資産として同一のhash付きファイルをページとWorkerから使用する。ページはclassic script、JSON Workerはclassic WorkerとしてIIFEをロードする。入口は即座に要求を受け付け、runtimeの準備完了を待つ。開発時はdynamic importでruntimeを読み込み、製品ビルドではViteがIIFEへまとめる。入口には型importによる `export {}` を出さない。通常版のdynamic importを残さない。描画の逐次化、SVGサニタイズ、JSON Workerの取消・期限・世代確認は維持する。

配布用原文・表示・パッチの固定スナップショットをリポジトリー内で管理し、通常buildで調査tmpや外部取得を必要としない。ビルド時にスナップショットの全ファイルと固定hashを照合し、既存の第三者ライセンス一覧からTiny内包物へリンクする。新しいPWA manifestにはTiny本体と同じ世代の原文を含める。旧キャッシュは現行SWの世代移行・回復方針に従って扱う。

## 実施結果

**本体接続・旧配布資産除去・原文導線・PWAの機能回帰は成功。ただしTiny 12.2.0の配布採用は、内包依存の脆弱性監査で不合格となったため保留する。main・配信先は変更していない。** [機械可読の証跡](evidence/mermaid-tiny-product-migration-validation.json)に生成物・実行環境・ソースhash・ケース別の成否を記録する。作業途中のため新しいcommitは作成せず、基点commitとソースhashで検証対象を識別する。

### 本体の変更

- rootの通常版 `mermaid` を固定版 `@mermaid-js/tiny@12.2.0` へ置換。root lockから `mermaid` と `elkjs` を除去した。調査用PoC・旧版の証跡や依存lockは履歴として保持する。
- 描画と構文検証は共通の `tinyLoader.mjs` で同じ資産をロードする。ページのロード失敗・不正API・15秒の無応答は拒否し、明示的な再試行を許す。Worker側は既存clientの期限・取消・終了・世代照合を利用する。入力の永続化は追加していない。
- JSON Workerをclassic形式に対応させた。ViteのWorker出力をIIFEに変更したため、converter Workerの出力形式にも影響する。PDF・Office・CSVと混在キューを回帰対象に含めた。
- 原文の固定スナップショット74資産を `docs/third-party-source-licenses/mermaid-tiny/12.2.0/` に配置。取得済み材料のhashを確認してから一覧の文言とmanifestの配置先だけを製品用に適合させ、原文・権利表示・パッチのbytesは保持した。製品は `/licenses/index.html` → `/licenses/mermaid-tiny/index.html` から到達する。DOMPurify 3.4.12はApache-2.0を選択と明示し、MPL原文も保持する。由来原文候補と生成器参考資料は役割を区別して表示する。
- 通常buildは固定スナップショットを全件照合してコピーし、調査tmp・PoC生成物・ネットワークを入力にしない。欠落・改変・余分なファイルは拒否する。Tiny本体もbuild開始時と配布物検査時に固定hashを照合する。

Tiny本体は2,811,424 bytes、SHA-256 `ea0cdf04eb31907eb20d956a34fe300095365c876887b54ffa29f1f847f56d00` の公開npmファイルと同一。root npm原文の対象は117組、Tiny寄与の63組は別の内包物一覧であり、この数をそのまま重複排除済みSBOMとして加算しない。原文68点・権利表示・パッチ2点・生成器参考原文・一覧・manifestを同じPWA世代に含める。配布物検査は通常版chunk・ELK実装の識別子・root lockとTiny hashを併せて照合する。単なるELK文字列の検索だけで不在と判断しない。

E2Eは変更範囲とリスクに基づく**対象ケースのみ**。Worker形式の変更により実WASM・PDFの品質/失敗分類、選択PDF、PowerPoint、Excel、DOCX、CSV混在、JSONとの取消・結果保持を含めた。200ノード・50 KiB等の既存境界は単体と先行PoCの証跡に加え、本体の実生成表示上限ケースを実行した。全件・別ブラウザー・実配信・インストール済み実機PWA・実容量不足は実施していない。macOS/iOSとiPhone相当のテストは対象外。コピーAPIの本文検証は試験用代替であり、OS実クリップボードはユーザー実機確認へ残す。

通常版からの移行試験には、固定Git commitの内容から変更前製品をローカルに作成した。UIタイトルと無害なWorker識別マーカーだけをfixture用に変更し、旧通常版Mermaid・ELK資産を持つ450資産のAと、新Tiny版Bを比較した。Aタブがある間はAを保持し、遅延Workerをオフラインで使用できること、旧タブ終了後にBへ移行すること、BでオフラインTiny描画と原文68点・表示・参考原文・パッチのhashが一致することを確認した。Bの取得失敗・資産消失・修復・旧v1制御からの回復も成功。旧キャッシュを稼働中タブから強制削除する変更は加えていない。

### 検出した問題と再発防止

1. **開発時のclassic入口（実装問題・テスト観点不足）。** 型だけのstatic importでも開発時変換が `export {}` を出し、classic Workerが `Unexpected token 'export'` で起動できなかった。製品IIFEビルドでは消えるため、製品E2Eだけでは検出できなかった。入口を型queryへ変更し、早期要求を保持してruntimeを待つ形にした。開発画面の同一ケースで回復を確認する。
2. **開発時の監視と遅延依存探索（環境/設定問題）。** 大量の調査ファイルを持つ作業環境ではページ初期読込が停滞した。rootのindexだけを入口とし、tmp/experimentsを監視対象から外した構成で解消。続いて初回Worker読込による依存再最適化でページが再読込され、入力が失われた。traceでナビゲーション2回を確認し、jsonc-parserとMarkdown解析依存を先に準備する設定で同一ケースが成功した。タイムアウト延長は行っていない。
3. **制限付き一時領域（環境問題）。** 最初の単体試験は一時ファイルrenameがEPERMとなり、テスト本文を実行できなかった。権限を確保した実行で再検証し、結果を製品不具合と混同しない。

開発画面を検査する `npm run test:e2e:tiny-dev` を追加し、CIでも製品E2Eの後に逐次実行する構成にした。今回はローカル実行であり、GitHub CIでの実行成功を示すものではない。

### 内包依存の脆弱性照合：配布採用は保留

通常のroot npm監査は本番・全依存とも0件だったが、Tinyは平坦化したJSに内部依存を持ち、npmの依存欄ではそれらが見えない。[別途の内包依存監査](evidence/mermaid-tiny-embedded-advisory-review.json)では、固定ビルドの寄与63組をnpm aliasで別々に表現し、同名の複数版も落とさず照合した。metadataの対象数63と入力一覧を確認。**該当2依存（最高重大度critical 1、高1）**となり、`npm run audit:tiny` は終了コード1。

|対象|公開情報との一致|現在の扱い|
|---|---|---|
|DOMPurify 3.4.12|[SAFE_FOR_TEMPLATESとshadow root/DOM出力に関するcritical](https://github.com/cure53/DOMPurify/security/advisories/GHSA-cg2g-xh64-v4q7)等5 advisory。修正版の候補は3.4.17|Tinyに当該版が含まれることは固定ビルドで確認済み。アプリでXSSが再現したという意味ではない。各条件の到達性は未確定で、例外承認はしない|
|js-yaml 4.3.0|[空のmerge元でCPU制限を回避するhigh](https://github.com/nodeca/js-yaml/security/advisories/GHSA-2883-xcg3-v3hh)等2 advisory。修正版の候補は4.3.2|JSONから生成するソースはflowchartで始まり、固定上流のfrontmatterはJSON_SCHEMAを使う等の到達性を絞る手掛かりはある。これだけで全advisoryの適用外と断定しない|

ここでのcritical/highは公開advisoryに基づく**依存版の分類**。本アプリで致命/重大な攻撃経路が成立すると確認したものではない。CSP、SVG除去、固定生成コードと対象安全性試験の成功だけで、版一致の指摘を解消済みとも扱わない。初回の診断は名前で集合化して同名複数版を落とす不足があり、最終スクリプトではaliasで全63組を保持する形に直した。

通常のnpm監査だけでは検出できない観点不足を、`audit:tiny` とCIの独立ゲートへ反映した。現候補ではこのゲートが不合格になるため、**CIのマージ可能な成功状態を主張しない**。GitHub CIは未実行。脆弱性例外や自動 `audit fix` は追加していない。

公開npmのlatestは照会時点でTiny **12.3.0**。版とintegrityのmetadataだけを確認し、取得・採用・内部版/由来/原文照合は行っていない。次はこの公式修正版候補を先に比較し、未解消なら更新依存からの再生成案と到達性の詳細検証を比較する。rootのDOMPurify/js-yamlを追加・overrideするだけでは、既に平坦化されたTiny内部のコードは置換できない。候補を変更する場合はbundle・寄与一覧・原文・PWA世代を再固定する。

## 次に残す作業と公開判定

1. **内包依存の監査指摘を解消する。** Tiny 12.3.0を候補として実bundle内の版・出所・条件を照合し、必要な比較試験を行う。現12.2.0を配布採用済みにしない。その後に本ローカル差分と固定スナップショットをレビューし、候補commit/lock/生成物を再固定する。マージは今回行わない。
2. Windows実機でのコピー/保存、実倍率・キーボード、PWA実インストール・復帰・容量等の対象項目をユーザーが確認する。macOS/iOSは対象外。
3. anydoc/PDFiumの内包物・原文・告知・必要な提供条件は既存の別管理を継続する。Tinyへの変更で完了扱いしない。
4. 許可された実配信先で本文hash・MIME・原文導線・更新/オフライン/回復を確認し、公開条件の充足に基づいて判断する。現時点で公開承認や検証デプロイを行わない。

本Tiny候補からELK実装を除いたため、**この候補のために旧ELKの生成器/checkout追跡を続けることは必須としない**。旧評価版・既公開版に関する証跡と義務を消したり、遡って条件充足と判定したりしない。[配布準備方針](distribution-adopted-policy.md)と [旧候補の判断表](distribution-decision-register.md)には新候補への参照を追記した。切戻す場合は旧実装・依存・原文・PWA manifestを一組として扱い、その版の公開条件を別途確認する。
