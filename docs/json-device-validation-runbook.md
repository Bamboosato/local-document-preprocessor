## 前提と証跡

macOS SafariとiPhone Safariの実機、Windows Chrome/Edge、NVDAまたはVoiceOverを用意する。OS・端末モデル・RAM・ブラウザー版・PWAのインストール有無・コミット・lockfile・電源／省電力・空き容量を記録する。Playwright WebKitをSafariと記載しない。

実機は専用のHTTPS検証オリジンで使用する。localhost以外の平文HTTPではSWが動かないため代用しない。公開・配信の承認と適切な配信環境を別途用意してから開始する。今回この配信は行わない。既存4187の試作と追加4188の静的Worker候補を別オリジンで提供し、方式・ビルドを区別する。

1. 未保存文書がないことを確認してから、その検証オリジンだけのSW・Cache・ストレージを初期化する。他オリジンや実利用データは消さない。
2. 通常ネットワークで初回取得、SW active・制御状態・資産取得完了を確認する。冷状態は別の新規プロファイル／オリジンで作り、温状態からの推測で済ませない。
3. fixtureは合成データのみ。入力本文・ファイル名・Pointer・値・URLのクエリを含むHAR、無加工スクリーンショット、コンソールを共有しない。ID、条件、時間、件数、一致判定、メモリの集計、マスク画像のみ保存する。
4. 一台では一つずつ試験する。負荷・計測・ビルド・他の自動化を並行しない。失敗は初期化した新規状態から最低もう一度再現し、単独と通しの差を記録する。
