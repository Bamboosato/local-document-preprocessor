# JSON採用方式の実装・Windows追加検証結果

実施日: 2026-10-26 / 基準: `6fe08bc`＋本PRの後続変更。\
決定: [採用方式と対象範囲](json-adoption-decision.md) / 観点・ケース: [追加計画](json-adoption-followup-plan.md)。

## 現在の判断

**独自SVG表示＋静的URL Workerを採用済み。macOS/iOSは今回対象外。本体統合は、Windows向けの残条件を満たすまで保留。** 方式採用の未決定状態とApple環境待ちは、今回の停止理由には含めない。

独立試作へ、全体表示・拡大縮小・100%復帰、図/ソース切替、図領域のキーボード移動、検証済み本文を維持した図再試行を実装した。製品の`src/`・production SW・root依存/lockfileには接続していない。出力のMermaidソースは従来の固定版検証と全量照合を維持する。

まず防ぐべき致命的不具合は未検証ソースの公開、文字・辺の欠落、入力の送信・保存。今回の対象検査では検出していない。重大な残存リスクは、Windows実操作・OS復帰/容量制限・インストール済みPWA、製品キューへの接続時の状態混入等である。試作の成功を製品全体の受入完了にはしない。

## 変更内容

- `diagram-view.mjs`と外部CSSで表示操作を追加。倍率は0.1%～400%に制限し、限界の操作を無効化する。全体表示は最大図を表示窓へ収め、100%に戻すと全ラベルへスクロールできる。SVGのwidth/heightだけを変更し、元ラベル・辺・Mermaid本文は変更しない。
- 検証完了前はソース欄を空にし、切替・出力を停止する。描画だけの失敗では検証済みソースへ切り替え、図再試行は新Workerで図だけを再実行する。クリアで図・ソース・出力許可を失効する。取得回復やネット復帰だけでは自動再実行しない。
- `readiness-policy.mjs`で配信用CSPを共有。静的Worker、固定SVG要素とtextContentを維持し、HTML・外部画像・リンク・入力由来設定は受け付けない。
- 配布物へproduction依存118件の原文119ファイル、版・取得元・integrity・リポジトリ情報の一覧を出力する。原文等の欠落はbuild失敗。実行資産の先行Cacheへライセンス文書は含めない。
- CIに試作SDKのChromiumによるAD/UP検査を追加し、専用previewとケース用サーバーを開始・終了する。スクリプト・ブラウザーは逐次実行し、証跡に本文を出さない。
- 要件・画面設計・作業指示へ採用決定と対象範囲を反映。先行報告は当時の履歴として保持した。
- PR更新で自動Previewを作成しないよう、`vercel.json`で当作業ブランチだけGit自動デプロイを無効化した。[公式Git設定](https://vercel.com/docs/project-configuration/git-configuration)に従い、他ブランチの設定は変更しない。マージ・デプロイ操作は実施しない。

## 更新失敗の検証境界

UP検査は同じビルド資産をケースごとの独立localhostオリジンから提供し、SWの世代識別と故障注入だけを変更する。2タブでは新SWをwaitingのまま保持し、全タブ終了後にactivate完了を条件待ちしてから開き直す。旧自Cacheだけを削除し、別用途Cacheと作業中の検証済み本文を保持することを確認した。更新後の再読込では入力・結果を復元せず、取得済み資産から新Workerをオフライン起動できた。

UP-02は配信サーバーが実際に新資産404を返す負の条件。UP-03/04は新SW内のCache APIだけへ例外を注入した。これらは実ブラウザーのinstall失敗・旧版維持の証拠であり、OSの空き容量枯渇、実権限拒否、OSへインストールしたPWA更新を証明しない。

## 最大入力・結果・図・WASMの追加診断

G02-M02は既存4187ハーネスのChrome CDPでUI/JSON Workerのheapとbacking storageを段階測定する。合成PDFを実WASM変換した後、各50 MiBのJSONに約1 MiBの配列と大きい兄弟値を置き、配列だけを出力して20結果を保持した。解析セットは常に1以下、20結果は明示置換まで維持した。入力合計は1,048,576,000 bytes。これは専用fixture群の保持試験であり、製品の20ファイル受付UIの受入確認ではない。

|段階|明示GC|UI heap MiB|UI backing MiB|JSON Worker heap MiB|Worker backing MiB|完了結果|
|---|---|---:|---:|---:|---:|---:|
|基準|あり|1.26|0.01|0.79|0.60|0|
|合成PDFのWASM変換後|なし|1.36|0.02|1.97|1.24|0|
|最大入力20件と20結果|あり|54.76|50.01|2.26|51.23|20|
|最大入力20件・20結果＋最大図|なし|57.08|54.95|2.67|51.42|20|
|図を含むGC後|あり|55.46|50.01|1.94|1.27|20|
|入力/結果の明示置換・図クリア後|あり|1.47|0.01|1.93|1.23|0|

heap合計のサンプル最大は61.17 MiB、backing合計のサンプル最大は203.00 MiB（別々の最大値）。File/Blobのネイティブ領域、OS常駐量、WASM処理中・図Workerの瞬間ピーク、低メモリ環境は含まない。**入力合計約1 GiBがこのheap値に収まるという意味ではない。** 元fixture文字列や大きい解析が解放される傾向は確認できたが、真のピークや自然GCの回復時間は未確認。解析・図は比較用ハーネスであり、採用UIと製品CSPを組み合わせた最終メモリの証明でもない。

## 配布資産・ライセンス

現在の先行取得対象はHTML・entry JS・CSS・検証Worker・配置Worker・静的faviconの6ファイル、計5,190,483 bytes。ライセンス原文119ファイルと`licenses/index.json`は配布物に含めるが、実行資産Cacheには含めない。汎用Mermaid検証バンドルは約5.18 MBを占め、これ以上の最小化は別の設計検討である。

初回収集では`khroma@2.1.0`にlicenseメタデータがなくbuildが停止した。原文`license`ファイルは存在するため、宣言欄はnullとし`not-declared-original-included`を記録して原文を配布するようにした。SPDXを推測して埋めたり原文欠落を許容したりしていない。原文・取得元・integrityが欠けた場合はbuild失敗を維持する。

機械収集と原文同梱は確認済み。EPL-2.0等を含む推移依存について、実配布バンドルの対応ソース提供やNOTICE等の条件を満たす最終確認は残る。全依存の保守的な収集結果を、法的配布条件の確認完了とは扱わない。

Git管理外`experiments/json-gates/evidence/`の`adoption-chrome/edge.json`、`update-chrome/edge.json`、`readiness-chrome/edge-adopted.json`、`memory-adopted-chrome.json`が今回の結果。マスク画像は`adoption-*-controls.png`。CIは`adoption-chromium.json`・`update-chromium.json`とマスク画像をartifactへ保存する。入力本文・ラベル・実行URLはログへ出さない。

4. 製品の混在キュー、再確定、別ファイル完了結果保持、コピー/DL/frontmatterの接続設計を完成させる。現在の表示操作は図層であり、製品UI-26全体の受入完了ではない。
