# 配布調査・接続レビュー・実機手順の追加計画

2026-10-27。PR #17を更新する。本体統合、実機操作、macOS/iOS、マージ、デプロイは行わない。配布条件調査→接続設計レビュー→ユーザー向けWindows手順の順に実施する。

## ケース前の観点

最優先は、異なる版のソースを対応済みとする誤判定、未検証出力の公開、ファイル/設定間混入、入力の保存・送信を防ぐこと。

|観点|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|固定版と出典・原文を照合|不一致/取得失敗/不明な版は未完了|同一crate名の複数版、workspace依存を区別|調査候補→確認済み事実→配布の未解消条件|
|非機能|公開一次資料を読取専用で調査|ネットワーク失敗・過大応答を制限|上限bytes/要求時間、固定commit|再取得で差異があれば更新証跡を残す|
|データ|hash・SRI・lockを照合|metadataだけのライセンス判定、未検証attestationを信用しない|lock全体とWASM対象graphを区別|版更新時に確認を失効|
|UI|利用者が実行できる操作/前提を手順化|検証できない機能を成功扱いしない|200%実倍率、狭幅、タッチ任意|初期化→操作→復帰→後片付け、未実施を記録|

## 調査・レビューの意図

- DS-01～04: SRI不一致、原文hash、Cargo.lock候補の厳密な区別、attestationの内容確認と署名検証の分離を小さな合成データで検査する。調査スクリプトを製品/CIの通常ビルドから呼ばない。
- DS-05～08: 固定snapshotを現在のlockと原文/バイナリへ照合し、WASM対象未確定・原文未収集・署名未検証の区分を保持する。手動準備のdescribeだけを実行し、ブラウザー起動・実機判定を行わない。入力オプションの曖昧さも検出する。
- DR-01: npm固定版のmetadataとlockのSRI、取得tarballを照合し、対応commitの生ファイルをhashで照合する。上流コードは実行しない。
- DR-02: anydocの固定Cargo.lockから候補を抽出し、同版crateの公開metadata/checksum/宣言を照合する。全候補がWASMへ入ったとは判定しない。
- CR-01～08: 設定版・解析世代・要求ID・runId・図世代を使う接続設計を、取消/失敗/応答逆転/削除/再試行/出力の順で机上追跡する。製品実装の試験とは区別する。
- WR-01～06: 実読み上げ・実倍率・タッチ・PWA・容量/メモリ負荷の手順に、固定版、前提、期待結果、停止条件、証跡、復旧を定義する。未提供のインストール機能等は「前提未成立」で止める。

今回は調査スクリプトの単体と文書・構文検査を対象にする。既存の製品/試作ランタイムへ変更がなければローカルE2Eは未実施とし、既存成功を今回の再実行として数えない。CIの既存選定規則は変更しない。同一Windows実機でスクリプトを並列実行しない。
