# 本体PWAの世代固定・更新回復計画（CUR-03）

PR #21を固定headでマージ後、main `5ad41ecf2df8e68369948337b92529880f5113b4` から検証ブランチを作成する。新PRのマージ・デプロイはしない。macOS/iOS対象外、実機はユーザー別途。

## テスト観点（ケース詳細化に先立つ）

最優先は致命な入力/結果の永続化、重大な世代混在・旧タブの無警告破棄・更新失敗後の回復不能を防ぐこと。

|観点|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|HTML/JS/CSS/Worker/WASM/図/原文を同一世代に固定|取得/ハッシュ/MIME/保存失敗では更新不成立|未取得の遅延資産、複数タブ|旧A稼働→B待機→全A終了→B起動、旧v1から移行|
|非機能|全資産を列挙し取得を逐次実行|Cache拒否/容量不足/部分削除から明示回復|大きなWASMと全原文、二世代の保持|install失敗時に旧キャッシュ維持、activate後だけ旧世代整理|
|データ|キャッシュはビルドの静的許可一覧のみ|POST/クエリ/外部/ユーザー文書を保存しない|許可外asset・破損応答・リダイレクト|入力/完了結果はメモリのまま、勝手に再読込しない|
|UI|準備中/未制御/待機/失敗を区別|オフライン不可を成功表示しない|保存すべき結果と複数タブ|手動再試行、保存後の再起動案内、取得失敗後の復帰|

## 実行範囲・証跡

実際の本体を二世代ビルドしてローカル同一originで切り替える。旧世代の未使用JSON Worker/図/WASMをサーバー更新後も利用できるか、結果が維持されるかを確認する。Cache障害・容量不足・改ざんは単体sandboxで原因を限定し、ブラウザーではネットワーク障害/更新待機/キャッシュ欠落を確認する。fixture ID・件数・世代ID・成否だけを記録し実文書やPIIは使わない。

SWは全アプリに影響するためChromium全回帰、PWA対象はChrome/Edgeを順番に実行する。同一端末で並列実行しない。headlessや故障注入の成功を、インストール済みPWAの復帰、実容量、OS/実機の証明と扱わない。

## 採用する接続設計

ビルド後に配布物一覧とSHA-256を生成する。HTMLに世代IDを付け、SWには確定一覧を埋め込む。installは全資産の検証/保存完了を条件とし、新規の失敗キャッシュだけを破棄する。skipWaitingとclients.claimによる強制移行は使わない。待機中は結果を保存して全タブ/PWAを閉じるよう案内する。

通常fetchは現世代の許可資産だけを返し、欠落時も同じハッシュの応答だけで修復する。ページ制御前の初回や旧v1は準備済みと混同せず、明示的な再読込/再起動を案内する。Cache失敗だけで入力/完了結果を消さない。全資産の事前保存には容量と通信量が必要で、失敗時はonline利用と旧世代維持を優先する。
