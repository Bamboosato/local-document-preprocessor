## 先に固定する検証観点

最優先は、必要な権利表示・原文・対応ソースの欠落、誤った提供済み表示、版の取り違えを防ぐこと。機能は一覧と導線、非機能はオフライン・容量・可用性、データは版/hash・原文・NOTICE と除外、UI は選択条件とリンク表示を確認する。正常は一覧と原文が開けること、異常は未提供・欠落・不一致、境界は複数ライセンス・空/複数 NOTICE、状態遷移はオンラインからオフライン・旧版から新版を区別する。実ブラウザー試験には合成入力を用い、実機・実配信と分ける。

## 原文確認と候補の分析

[EPL-2.0 原文](https://www.eclipse.org/legal/epl/epl-v20.html)3.1 は対象 Program の配布に伴うソース提供と取得案内、3.2 はソース配布の条件、3.3 は既存の権利表示・免責等の削除・改変を禁じる。3.3 はソース提供の免除ではなく、[旧報告](distribution-license-review.md)の誤記を訂正した。原文はバイト単位の再ビルド一致を明文の一律要件としていないが、対応するソースの範囲と提供の充足は別途確認する。

既存[anydoc 調査](evidence/json-anydoc-target-licenses.json)の96 registry 依存は、原文193件と workspace 原文2件の計195件。宣言式には単一条件、OR、AND、`/` 表記が混在する。例えば `encoding_rs 0.8.35` は `(Apache-2.0 OR MIT) AND BSD-3-Clause`、`unicode-ident 1.0.24` は `(MIT OR Apache-2.0) AND Unicode-3.0` であり、OR の一方を選ぶだけで AND 側を消さない。表記・原文・実対象と適用を個別に確認し、未確定のものを対象外としない。[PDFium の29原文候補](evidence/json-pdfium-source-licenses.json)には固定 source/DEPS 由来が含まれ、metadata の `shipped` は公開 WASM へのリンクを証明しない。いずれも候補の一覧で、対象外とする根拠・必要な追加原文・追加提供条件は今後の判断記録に残す。

宣言式の機械的な一次仕分けでは、上記 AND 2件、`/` を含む旧形式7件、`zlib-rs 0.6.6` の Zlib 単独1件を個別原文の確認対象とした。AND を含む2件の原文は収集済みだが、各条件の採否や告知義務は判定していない。残る候補も OR・単一条件を含み、機械的な分類や候補収集だけで必要な告知・対象外の確定に使わない。

## 公開前の4条件

1. **ELK ソース提供:** 対応範囲・版・既存権利表示・取得案内と、その対応根拠を確定し提供可能にする。
2. **WASM 原文・告知:** 候補について追加する原文・著作権表示、追加提供が必要な対象、対象外の根拠を個別に記録する。候補の大量同梱のみで完了扱いにしない。
3. **案内と提供物:** 原文・NOTICE はオフラインで閲覧でき、利用者が必要なソースへ到達でき、対象版と hash が一致する。ソース ZIP は PWA 事前取得から外す。
4. **公開版の受入:** 実配信先の本文 hash・MIME・更新・オフライン・回復と Windows 実機対象を確認。致命・重大の未解消は公開不可、軽微な残件は影響と対応予定を記録して判断。

完全な WASM リンク構成復元、byte 単位の再ビルド、全依存の source ZIP、PDFium テストPDF除外の単独事由、全項目の専門家確認は一律条件としない。ただし必要な条件を別の十分な根拠で確認することが前提。適用範囲を解決できない論点は必要に応じ専門家へ確認する。

判断記録は「対象版／適用条件／履行内容と証拠／未解決事項／公開可否／判断者・日付」を使用する。現状は準備方針を採用し、**公開可否は保留**。配布責任者案は正式承認とは分ける。実配信・公開済み提供物はまだない。
