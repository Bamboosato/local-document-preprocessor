## 採用前に決めること

1. **図表示方式。** 推奨候補は検証済みのJSON木専用Worker方式。Mermaid標準レンダラーそのものではないため、図の配置・折返しの違いを仕様へ明記する。採用しない場合は別方式を隔離試作へ戻し、同じG-04基準で比較する。Mermaid出力の廃止や画像への置換を暗黙の代案にしない。
2. **実端末と成立する上限。** macOS SafariとiPhone Safariの端末・OS・ブラウザー版、PWAの導入条件、読み上げ環境、性能測定方法を決める。最低対応端末やメモリ保証を未測定で宣言しない。
3. **資材とCSP。** 必要な解析・構文検証・配置・フォント資材を切り分け、同一オリジンへ同梱する。試作の全資材先行取得をそのまま製品化しない。Blob／data URLが必要なら静的コードだけを扱い、入力・生成Mermaidソースを実行URLへ埋め込まない。必要最小の許可を実ブラウザーで確認する。
4. **依存と検証環境。** 現候補は試作のlockfileに固定済み。採用時に版・推移依存・ライセンス・脆弱性を再確認する。Playwright 1.64.0は検証用であり、アプリの実行依存ではない。root側のSDKとの版差とWebKitの既知の模擬不具合を踏まえ、CIで使う環境の統一を別差分で検討する。

採否や上限を変える場合は、要件・画面設計・期待fixture・利用者向け説明を同時に更新する。安全性・値の完全性を下げる変更は、この計画だけでは承認しない。

### 実機測定の負荷と前提

- 新規状態、小入力1件、大入力1件、連続切替、複数完了結果を保持した混在処理の順に負荷を上げる。50 MiB・100,000ノード・深さ128等は、それぞれ成立する入力と組合せを識別する。50 MiBの空白だけを最悪負荷の代用にしない。
- 20ファイルの元File参照を持つ状態と、20解析木を同時に持つ状態を区別する。原則1解析セット、一度に1入力、表示窓300行・詳細10,000コードポイントの予算を確認する。
- 元File／Blob、復号文字列、解析木、転送・一時コピー、完了済みMarkdown／plain text、図・WASMを含めた総メモリとピークを測る。明示GC後のJSヒープだけを根拠にしない。取得不能な指標は、利用した観測方法と限界を記録する。
- 初期上限は50 MiB／ファイル・20ファイル、本文10 MiB、表10,000データ行、一覧表100データ列、図200ノード／ラベル200コードポイント／コード50,000コードポイント。最大値の組合せや完了結果の保持を検証し、成立しなければ正式な上限見直しへ戻す。
- 操作フィードバック300ms以内、取消後1秒以内の復帰は実機で測る目標。図資材15秒と描画5秒は別計測し、実中断・新コンテキスト再試行・期限後結果の拒否を確認する。OS停止中の応答保証や、背景復帰時の時計挙動はデスクトップ試験から推定しない。

### 本体で維持する状態と回復の契約

UIは元File・一意なID・確定設定／設定版・小さな検査サマリー・完了結果を持つ。Workerは原則1解析セットを持ち、UIへ全構文木を複製しない。業務状態と解析状態、図表示状態を独立させる。

全要求・応答は、ファイルID、構造検査世代、Worker世代、解析世代、Pointer、設定版、要求ID／実行IDの該当組合せで照合する。キャッシュ追い出しや再解析だけで設定版を進めず、完了結果を破棄しない。不整合Pointerはエラーとして保持し、全体へ黙って戻さない。

|状態|許可する操作と回復|禁止すること|
|---|---|---|
|再解析中・適用可否の判定中|取消、状態表示。成功後に現設定の確定を可能にする|古い応答で確定を有効化、スタイルの自動変更|
|検証済み本文があり図表示だけ失敗|新しい図要求で再試行。本文・品質・出力・キューを保持|再試行のために本文を再変換、他項目の再実行|
|生成／構文検証が未成功|「変更→同じ設定も再確定可能→変換開始」で再変換|コピー・ダウンロード、図再試行への流用、復帰だけで自動実行|
|取消・クリア・再選択・設定更新|該当世代の処理と図コンテキストを破棄|旧結果・旧図・旧フォーカスを復活させる|

## 検証範囲と統合完了の条件

- 計画書だけの変更は文書リンク・構造・差分を検査する。アプリE2Eは実行しない。
- 隔離試作の修正は対象ケースを先に追試し、方式・非同期制御・資材境界を変えたときは関係するクロスブラウザー検証へ広げる。前提依存を避け、単独と通しの両方を確認する。
- 本体の共通契約・Worker・描画依存を変更した段階では、仕様どおり全既存E2Eを1 workerで行う。JSON受入ケースと既存回帰をどちらも含め、CIの自動スコープ選択も満たす。局所修正の追試は影響に応じて絞り、最終の共通経路検証を省略しない。
- 最終確認対象はChrome、Edge、実macOS Safari、実iPhone Safari。PlaywrightのFirefox／WebKitは補助対照であり、実Safari・実PWAの代用にしない。背景状態、OS・フォント・保存権限、ネットワーク、負荷を記録する。
- 各結果に実施範囲・選定理由・未実施範囲・残存リスクを記載する。同一実機でスクリプトを並列実行しない。本文・PII・秘密情報・不要なパスはログ／証跡へ含めない。

完了判定には、G-01～G-04と全受入条件の証跡、実機で成立する上限、`npm run check`、`npm run audit:security`、`npm run test:security`、`npm run check:docs`、必要なE2E、配布ライセンス・CSP・SW更新検査を揃える。致命・重大な未解消事項があれば停止する。仕様・README・構成・試験方針の差異を解消してから、指示された範囲のPR・マージ・公開へ進む。
