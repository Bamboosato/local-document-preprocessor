# 標準Mermaid表示の計画・検証観点

2026-10-30。ユーザー承認によりknowledge-board同等の表示基準へ変更する。基点main `4ad8947`。本体統合・macOS/iOS・実機・マージ・デプロイは対象外。

## ケースより先の観点

最優先は、入力の実行/外部送信、未検証本文の公開、旧描画や別文書の混入、表示失敗による検証済み本文の欠落を防ぐこと。標準描画の同期処理を強制中断できるとは保証しない。

|観点|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|JSON生成→別Worker構文検証→標準render→図/ソース|検証失敗は出力禁止、描画/資産失敗はソース維持|生成上限と表示50 KiBを区別|新規→表示、連続変更、clear、dispose|
|非機能|ローカル資産を遅延取得、300ms debounce、描画逐次化|ロード拒否、同期停止を強制中断と誤認しない|過大ソースは描画前に停止|古いpending/エラーを破棄、再試行|
|データ|文字・数値・Pointerの元生成契約維持、SVGをサニタイズ|script/foreignObject/on属性/危険URL/外部参照を除去|51,199/51,200/51,201 UTF-8 bytes、CJK/絵文字|出力許可は検証済み本文へ束縛、Storageへ保存しない|
|UI|図/ソース、読取専用、状態/エラー、スクロール|上限/失敗を日本語表示、空白の成功表示を防止|200ノードの合成図、狭いviewport|ソース切替、旧要求完了、再読込で空|

## ケースと意図

- SM-01: 正常JSONからの生成ソースを標準描画し、全ラベル・親子辺と検証済み本文を照合する。
- SM-02: 50 KiB前後をUTF-8で判定。超過時renderを呼ばずソース/出力を保持する。生成の50,000コードポイント上限を置換しない。
- SM-03: 危険SVG fixtureと生成時の危険文字列を検査。DOM実行・外部要求・入力保存が起きないことを確認する。
- SM-04: A→B、A→clear、旧成功/旧失敗の遅延完了とdisposeで旧図を採用しない。単独/通し両方を実行できる初期化を持つ。
- SM-05: 描画例外/資産取得失敗→明示再試行、ソース切替。検証済み出力を維持し、検証失敗は出力不可のままとする。
- SM-06: 200ノード、絵文字・制御文字・数値を含む合成fixtureを検査。スクロール・図/ソース操作はUIを通す。
- SM-07: 再読込でソース・結果なし。Storage/Cacheへの本文保存なし、外部HTTP要求なし。
- SM-08: 新しいcontextで実際の遅延Mermaid chunk取得を拒否し、本文維持を検査。module取得失敗がブラウザーに残る場合の回復は、入力を保存せず再読込・明示再生成とする。

ローカルは新規表示を対象とするChrome/Edgeのheadlessクロスブラウザーを同一実機で逐次実行する。実機受入の代替にしない。CIではChromiumで同ケースを実行する。旧独自SVG試作は履歴として残し、旧試験成功を新方式の証拠へ流用しない。root製品E2Eは変更せず既存CI selectorへ委ねる。新方式のPWA install/更新/実負荷・読み上げ・実200%ズーム・タッチは未実施として残す。

証拠はfixture ID・成否・件数・hash・ブラウザー版だけ。本文/Pointer/個人パスをログへ記録しない。異常時は原因を実装/データ/環境/観点不足に分け、現象の再現と修正後の対象検査を行う。
