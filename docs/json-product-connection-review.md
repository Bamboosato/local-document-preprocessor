# JSON接続設計レビュー記録

2026-10-27。対象は[接続設計](json-product-connection-design.md)と要件J-RC/UI-26、既存の`App.tsx`、`processQueue.ts`、`ConverterWorkerClient.ts`、`ResultCard.tsx`、`files.ts`の接続境界。製品へのJSON接続は未実装であり、以下は設計の机上レビューである。実装不具合や実機試験成功を主張しない。

## 観点と前提

[追加計画](json-followup-review-plan.md)の機能/非機能/データ/UIと、正常/異常/境界/状態遷移を使う。初期状態はJSON A/Cと既存形式Bが独立fileIdを持ち、Aには設定版s1の完了結果があること。本文・値は合成fixtureの識別子として扱い、記録には本文を転記しない。

## 追跡結果と設計への反映

|ID・影響|追跡した事象と意図|レビュー結果/対応|統合後に必要な検査|
|---|---|---|---|
|CR-01・致命|Aのdraft対象aへのdetail待機→対象bへ変更→a応答→閉じて同じAを再度開く。確定版s1は変わらない|確定版だけではdraftを区別できない不足を補完。dialogSessionId/draftRevision/操作別requestId/対象を照合し、旧応答では確定を有効にしない|同一dialog内の応答逆転と、閉じる→再オープン後の旧応答を別々に注入|
|CR-02・重大|A完了→C解析でAキャッシュ追出し→A再読込失敗/取消。完了結果の保持が目的|旧方針を維持。非同期解析応答は世代照合するが、確定済みA結果を現在のcache世代へ従属させない|再解析成功/失敗/取消のすべてで設定版と完了結果を保持、B結果も不変|
|CR-03・致命|Worker終了→新WorkerでrequestIdが同値→旧イベントが遅延到着|Worker世代が設計本文で欠けていたため明記。client側の世代を増加し、旧pendingをreject。必須属性・operation・型も検査|再生成直後の旧success/error/detailと未知operationを注入し、設定・出力不変|
|CR-04・致命|A生成成功→構文検証中→全体取消→検証成功→B待機。未検証の成功表示を防ぐ|JSON taskのresolveは本文検証後。取消後のresolveはrunIdで不採用。図配置は別層で、配置失敗でも検証済み本文を失敗へ格下げしない|生成後/検証中/配置中で取消を分ける。Bは開始せず、既に完了したCを保持|
|CR-05・重大|ルートPointer空文字で項目表→一覧表→Mermaidへ変更、図資産未取得|ルートと未選択を区別。表にMermaid成功を要求しないスタイル別proofを定義。旧図のoutputAllowedを表/新版へ流用しない|ルート、escaped Pointer、一覧表不適合、各上限±1、図検証資産失敗を組み合わせる|
|CR-06・致命|旧ResultCardから出力操作→A再確定/削除→非同期コピー完了|操作開始時のlive state照合と本文snapshotを明記。完了通知は同じ結果にのみ反映。OSへ開始済みのコピー撤回は保証しない|古いhandler、許可false、コピー権限拒否、完了後に異なる結果が表示される場合を検査|

## 受入の境界

既存ICの混在/取消/出力純粋関数の成功は、上記の世代・UI配線を証明しない。現在の試作は製品の設定状態の所有者ではないため、製品ResultCardにJSONを接続した証拠にもならない。型定義、adapter、client、reducer/UIと実コピー/DLの受入は、本体統合の許可後に実施する。

まず防ぐべき設計リスクは、古い要求の採用、未検証結果の公開、出力操作の古い許可利用。今回その防止条件を具体化したが、実装済みとしてゲートを通さない。
