# ADR-0003: 安定境界単位の逐次変換によるページ区切り

## 状態

採用

## 背景

PDF ページと PowerPoint スライドの境界を Markdown の独立行 `---` として残す必要がある。一方、anydoc WASM の Markdown API は文書全体の文字列を返し、PDF の document model や変換後文字列上のページ位置を提供しない。変換済み本文から境界を推測すると、同一文字列の反復、空ページ、表、文字欠落時に誤った位置へ区切りを入れる可能性がある。

## 決定

- UI は PDF／PowerPoint にだけページ区切りオプションを表示し、既存 Vercel 版と同じく既定オンとする。
- Worker は先に選択範囲だけの入力を再構成する。
- オプションがオンで2単位以上ある場合、再構成入力を1ページ／1スライドずつ客観的な構造境界で切り出し、同じ Worker の同じ Converter で順番に変換する。
- 各 Markdown を trim し、境界間だけ `\n\n---\n\n` で結合する。先頭・末尾には挿入しない。
- オフ、1単位、安定境界がない形式は従来どおり文書を1回だけ変換する。
- PDFium fallback も同じ設定を使用する。plain text は Markdown thematic break を空行として扱い、`---` を残さない。
- 単位変換に失敗した場合は文書全体を失敗扱いとし、境界や欠落を推測して success にしない。

## 結果

- 区切り位置は文書構造に基づき、変換後本文の推測に依存しない。
- 選択した N 単位に対する区切り数を N-1 件として決定的に検証できる。
- オプションがオンの文書は anydoc 呼び出し回数と一時的な再構成コストが単位数に比例する。単位処理は並列化せず、既存の Worker 破棄によるキャンセルを維持する。

## 却下した案

- anydoc の文書全体出力へ後から文字列照合で挿入する: 反復文字列や欠落時に境界を誤る。
- PDFium テキストだけで常に Markdown を再構成する: anydoc の表・見出し等を失い、PDF 一次変換の責務を置き換える。
- 単位ごとの並列 Worker: メモリピーク、順序競合、iPhone Safari の安定性リスクを増やす。
