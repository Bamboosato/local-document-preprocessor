# ADR-0002: PDF のブラウザ内独立抽出比較と安全側フォールバック

- 状態: Accepted
- 日付: 2026-08-07

## Context

Type0 フォントで ToUnicode が欠落した PDF では、anydoc 0.1.7 の PDF 実装が
`UniJIS-UCS2-H` / `UniJIS-UCS2-HW-H` を復号できず、半角カタカナを含む日本語が
`U+FFFD` へ変化する実例がある。anydoc の成功だけでは文字欠落なしを保証できない。
文字を辞書や正規化で推測復元すること、既存サーバー製品へ自動送信することは要件に反する。

## Decision

- anydoc を一次変換エンジンとして維持する。
- PDF に限り、同じ Worker 内で PDFium WASM を遅延初期化し、全ページのテキストを独立抽出する。
- `U+FFFD`、異常制御文字、不自然な Unicode、Unicode map error、および Type0 / ToUnicode 欠落時の文字頻度差を比較する。
- PDFium 出力が非空、異常 0 件で、一次出力より客観的に改善した場合だけ、ページテキストから Markdown を再構成する。plain text はその Markdown から生成する。
- フォールバック採用時は `encoding_suspect` と `pdf_text_fallback` を付け、必ず `partial` とする。
- 改善を確認できない異常結果は `failed` とし、プレビュー・コピー・ダウンロードを停止する。
- 正規化、全半角変換、未知文字の推測置換は行わない。
- 画像のみは `failed`、テキストなしページを含む混在 PDF は `partial` とする。OCR は行わない。

## Consequences

- 既知 fixture と実 PDF の回帰文字列を Markdown / plain text の双方で完全保持できる。
- 二つの独立実装が一致または改善するという観測事実を診断根拠にできる。
- PDFium WASM 約 4.6 MB の同一オリジン取得と初期化コストが増える。現行の範囲選択実装では初回 PDF 構造確認時から使用する。
- 二つの実装が同じ欠落を起こす可能性までは排除できないため、`success` でも原本照合は残る。
- 変換後の独立抽出不能時は無警告成功にせず `partial`、構造リスク・文字異常・空出力があれば `failed` に倒す。変換前の PDF 構造確認に失敗した場合は、分類済みエラーとしてその時点で停止する。

## Rejected alternatives

- 文字列辞書による置換: 原文を推測し、別文書で誤修復するため不採用。
- NFC / NFKC 正規化: フォントマッピング欠落を解消せず、半角カタカナを変えるため不採用。
- サーバー版 pypdf への自動送信: ローカル完結要件に反するため不採用。
- 警告だけで出力を常に許可: 保証不能な文字列が後段へ渡るため不採用。
