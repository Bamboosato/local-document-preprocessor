# ADR-0005: 配布世代を固定したPWAキャッシュと待機更新

- 状態: レビュー用ブランチで実装・検証（mainへの取り込み・デプロイは別途）
- 日付: 2026-10-30
- 置換対象: [ADR-0004](0004-pwa-static-asset-cache.md)の取得時キャッシュ・network-first HTML・強制移行。静的資産だけを保存する境界は維持する。
- 観点・証拠: [計画](../pwa-generation-plan.md)、[結果](../pwa-generation-validation.md)

## 決定

1. ライセンス収集後に全配布ファイルのサイズ/SHA-256を列挙する。世代IDはSWテンプレートとHTMLへのID挿入前の配布物一覧から決定し、HTMLのmetaとSWへ同じIDを埋め込む。公開manifestのHTMLハッシュはID挿入後のbytesを表す。二重実行でも同じIDになることを検査する。
2. ブラウザー自身が保持する `sw.js` を除き、JS/CSS/Worker/両WASM/Mermaid遅延chunk/manifest/アイコン/原文とinventoryをインストール時に検証し、`ldp-static-<ID>` へ逐次保存する。完了標識は全件成功後だけ書く。新規の失敗キャッシュだけを削除し、既存世代は壊さない。
3. skipWaiting / clients.claim による強制更新はしない。制御中の旧タブがすべて終了するまで待機する。新旧のHTMLと資産を混ぜず、旧タブは旧キャッシュを使う。activate時の旧世代整理は、後続のinstalling/waitingを検出したら中止する。削除失敗だけで新世代のactivateを失敗させない。
4. fetchは同じ世代の許可一覧・ハッシュ/MIMEに一致する応答だけを利用する。欠落・破損は一致するネットワーク応答でのみ補修する。POST、外部、許可外文書、クエリ要求は保存しない。ルートへのクエリ付きnavigationは同じindexへ写像し、クエリをキャッシュキーにしない。
5. 最初の未制御ページと、制御済みのオフライン準備完了を区別する。未制御ページはオンライン利用を続けられるが、そのタブのオフライン利用には保存後の明示的な再読込が必要。未知の旧SWやページと異なる世代では新しい変換を止める。結果は消さない。
6. 更新待機は全タブ/PWAを閉じて再起動する案内だけを表示する。再取得は利用者操作で行い、オンライン復帰やcontrollerchangeだけで変換・再読込しない。
7. HTMLまで欠落し、旧HTMLを新しい配信から復元できない場合は503の復旧ページを返す。固定のnonce付きスクリプトだけで更新の準備を要求できる。通常アプリのCSPは緩めず、復旧ページも外部スクリプトやevalを許可しない。ここからも強制activate/reloadせず、他タブの結果保存と全終了を案内する。

## コスト・制約

現在の事前取得は約24MBで、JSONだけの利用でもPWA準備としてWASM等を取得する（JSON処理でWASMを初期化するわけではない）。二世代分の容量とブラウザーの追加領域が必要。保存拒否・容量不足では準備完了にしない。準備済み表示は完了標識/キーの存在を確認し、実際の使用時にもbytesを再検証する。永続的なCache保持・OS容量・常時オフライン動作を保証しない。

状態照会の2秒と、全資産再取得の120秒の待ち時間を分ける。再取得期限後もブラウザー側の処理が継続する可能性があるが、別世代を強制適用しない。旧v1を過去にさかのぼって完全オフライン対応にするものではない。

文書・結果・設定はCache/IndexedDB等へ保存せずメモリのみ。Cache内の追加情報はビルド世代・完了標識であり、File ID、文書名、本文、入力由来hashを含めない。macOS/iOS、実インストール済みPWAの復帰、実容量・配信環境は未確認として残す。
