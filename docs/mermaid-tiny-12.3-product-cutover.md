# Tiny 12.3.0 本体切替と回帰

2026-11-10。ユーザー指示により、12.3.0への本体切替、原文・権利表示・PWA・既定監査を同時に更新する。マージ・デプロイ・アーカイブの公開/添付は行わない。macOS/iOSは対象外、実機受入はユーザー別途。

**ローカル本体候補をTiny 12.3.0へ切り替え、既定監査と対象の本体回帰は成功した。** 通常の本番/全npm監査と、実bundleに結び付けた67対象の監査はいずれも0件。原文69点・ライセンス関連75資産を同一PWA世代に含めた。これはローカル候補の受入であり、mainへの反映・正式公開の承認ではない。

## 実装前に固定する検証観点

最優先は、旧bundleに新原文/監査を結び付けて成功扱いすること、追加MIT原文の欠落、更新中の文書間混入と未検証出力を防ぐこと。

## 既定監査と誤った合格の防止

引数なしの `npm run audit:tiny` は、[確認済み67対象](evidence/mermaid-tiny-12.3-audit-scope.json)を既定にした。内訳は第三者寄与63組、Mermaid/parser/Tiny自身の名義3組、DOMPurify内の生成helper対応版1組。単純な重複排除済みSBOMの総数や、全npm packageがそのまま同梱されたという意味ではない。

既定ゲートでは公開advisoryへの照会前に、次を検査する。

- package.jsonの固定版、lockの版/integrity、実際に入っているpackageの版を同じ12.3.0へ結び付ける。
- 実JSのサイズとhashが、原文・監査対象に対応する公開bundleと一致することを検査する。
- 監査用データのhash・生成元commit・bundle hash・対象数を固定版情報と照合する。同名複数版はaliasで保持し、同一組の重複は拒否する。

これにより、12.2.0が残ったまま12.3.0の一覧だけを監査して0件とする誤りを防ぐ。研究用に明示した別候補の監査は可能だが、その記録は本体へ結び付けた既定ゲートと区別する。今回の既定結果には `defaultGateBoundToInstalledRelease: true` を記録した。例外追加・指摘除外・自動 `audit fix` はしていない。

## 旧版と新世代を混ぜない回帰

切替前のローカル本体12.2.0を、原文と全静的資産を含む自己完結したAビルドとして先に固定した。fixture用の変更はタイトルと無害なWorker識別マーカーだけ。AのTinyは旧公開hash `ea0cdf04…`、原文台帳は旧版、Bは新しい12.3.0と69原文となることを検査してから試験した。

PG-01では、Aタブ2枚を開いたままBを準備し、旧タブの結果を保持した。B待機後も、旧タブからオフラインで取得した原文台帳のhashがAと一致し、**初回の遅延Worker/Tiny読込と図表示もAのまま成功**。旧タブを全て閉じてからBが有効化され、Bでオフライン描画・69原文/表示/パッチ/参考原文のhashが一致した。B取得失敗、失われた資産の修復、旧v1制御からの回復も対象5ケースで成功した。

さらに、通常版Mermaid 12.2.0/ELK資産を持つ固定main相当のAから新Bへ移るPG-01も成功。いずれも旧キャッシュを稼働中タブから強制削除せず、既存SWの待機・回復方針を保っている。これはローカル比較用ビルドと合成入力の結果であり、実配信先やインストール済み実機PWAの受入ではない。

## 問題の扱いと残件

今回の対象範囲で、新たな致命・重大な機能不具合は再現しなかった。版/原文の不一致による誤った成功は重大な管理リスクとして、上記の異常系で拒否を確認した。最初のbuildでJSON importの将来互換性に関するVite警告が出たため、import属性を明示し、警告を抑制する設定ではなく構文を修正した後に最終検証した。

旧ELK資産は今回の本体配布物・root依存に残っていない。旧版の調査資料・元のスナップショットと既公開版に関する証跡は履歴として保持する。12.3.0候補の由来・原文対応は [先行調査](mermaid-tiny-12.3-review.md)の固定hashで引き継ぎ、今回の本体実ファイルと照合した。

残す作業は次のとおり。

1. 固定したcommit・生成物一覧をレビューする。リモートCIの結果はPRに記録し、以下のローカル検証をGitHub CI成功とは表示しない。
2. Windows実機でのOSクリップボード、実倍率/キーボード、PWA実インストール・復帰・実容量などはユーザーが別途確認。全件・別ブラウザー・最大負荷の実行は今回の範囲外。
3. anydoc/PDFiumの原文・告知・必要な提供条件は別管理を継続し、Tiny監査0件で完了にしない。
4. 許可された配信先での本文hash/MIME、案内と提供物、更新/オフライン/回復を検証し、[配布準備方針](distribution-adopted-policy.md)に基づいて公開可否を判断する。

マージ・デプロイ・アーカイブ公開/添付は行っていない。実配信・実機の未確認事項を完了扱いせず、今回のローカル本体切替と回帰は完了とする。

## レビュー用の最終固定（2026-11-10）

対象の製品コードとテストを **`180f44c9e5039e2cbdb15af59f5bbb463b5c6562`** に固定した。本体切替本体は親commit `fb2c1c2`、続く差分はクリーン環境のテスト初期化2行だけ。後続の報告書・台帳および旧調査用検査の修正でも、この製品/本体テスト内容を変更しない。PRはmainの通常版Mermaidからの累積差分で、従前の隔離PoC・原文/由来調査・12.2.0の不合格証跡も履歴として含める。別のELK生成器調査PR #38の変更は取り込まない。

最終確認の観点は、機能=Git格納内容からのビルド成立、非機能=通常/内包監査と配信検査、データ=改行変換後の原文改変防止と全生成物の一致、UI=既に実施した本体対象33件のコード同一性。正常系は独立依存からの再生成、異常系は欠落した作業フォルダーと依存共有の拒否、境界は全221生成物/263固定資料、状態遷移は既存の作業環境からクリーンな検証環境への移行とした。

[最終生成物の固定台帳](evidence/mermaid-tiny-12.3-review-candidate.json)にsource commit/tree、コードのGit blobと確認した作業bytes、全221ファイルのサイズ/SHA-256、環境、監査、ログhashを記録した。PWA世代は **`429747bec5da3853ab4ffe06`**、全ファイル合計17,028,044 bytes、一覧hashは `65202cb357d66827d3614a6bc6e14554350ad4c7d423121ce44109e5f7a1cead`。生成物実体はローカルGit管理外に保持し、Gitにはhash一覧だけを含める。アーカイブの作成・公開・添付は行っていない。

Gitのステージ内容からWindows用コピーを復元し、共有依存を使わず固定lockで `npm ci` を実施した。単体124件/PWA11件成功、修正後の原文・版ゲート2件成功、build/配布物検査成功。独立ビルドの**221ファイルすべてが先の本体回帰で使った最終生成物とサイズ・hash一致**し、ローカルHTTP221件も不一致0。通常の本番/全npm監査および既定67対象監査は再実行して0件。コードと生成物が同じであるため、ブラウザー対象33件・追加移行1件・開発起動1件は先の結果を引き継ぎ、全件/クロスブラウザーを追加していない。

追加で検出・修正した問題は次の2点。

- **データ/環境の前提条件:** Windowsの `core.autocrlf=true` でハッシュ固定JSONがGit格納時に変わる。原文・証跡・版情報に `.gitattributes` の `-text` を指定し、上流CRLFも含めて263ファイルの格納bytes一致を確認した。CRLFを保持する範囲では `whitespace=cr-at-eol` を明示し、通常の空白検査は維持する。
- **テスト実装の前提条件:** 原文テストが既存の `tmp` を暗黙に利用していた。初回のクリーン検査では2件とも `mkdtemp ENOENT` となり、作業フォルダーをテスト自身で初期化する修正後、`tmp` がない状態から同じ2件が成功した。既存環境の成功だけでは発見できなかったため、クリーン復元で検出した。製品への影響はなく、未修正ならCI検査を止める問題。

最初の依存共有junctionではViteがコピーの外側にあるTiny URLを拒否した。これは検証コピーの環境問題として独立 `npm ci` に切り替えて解消し、製品のパス制限やCSPを緩めていない。途中の失敗ログはローカルに保持し、最終結果と区別した。

実機・実配信・正式公開は未確認。macOS/iOSは対象外。マージ・デプロイ・ソースアーカイブの公開/添付は行わず、レビュー用PRを作成する段階までとする。

### PR初回CIでの調査用検査の修正

[初回CI](https://github.com/Bamboosato/local-document-preprocessor/actions/runs/42755003298)では、本体側の通常/内包監査・単体・型・build/配布物・配信ガードが成功した一方、旧隔離試作のSL-09が失敗した。歴史的なanydoc/ELK/PDFiumの226原文と、その親フォルダー内の全txtを等値比較しており、新しいTinyの版別原文まで旧台帳に存在すると仮定していたため。

まず防ぐ問題は、検査を弱めて旧原文の欠落/余分な原文を見逃すこと。旧3領域の全226原文のhash/件数/過不足検査を保ち、Tinyは本体の75資産固定ゲートで別途検証する。親フォルダーの未知の領域・ファイルは引き続き拒否し、既存の `.gitattributes` のみメタデータとして許容した。ローカルで配布調査8件・原文ガード11件が成功。分類はテスト観点/データ境界の問題で、製品コードや最終221生成物は変更していない。後続CIの最終結果はPR本文に記録する。
