# G-04 代替方式の検証計画

本体統合は保留。既存の iframe 候補とその失敗証跡は保存する。

## ケース詳細化前の観点

まず防ぐべき致命的不具合は本文の外部送信・永続化・別世代混入、重大な不具合は中断不能と誤った検証済み表示。

|分類|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|検証済み構造図と元 Mermaid 出力を保持|構文検証失敗は出力禁止、描画失敗は検証済み出力保持|200ノード・200文字ラベル|中断→再試行、旧処理→新文書|
|非機能|重い処理は独立 Worker|同期処理6.5秒を5秒で終了、初期化失敗|5秒上限、15秒初期化|オンライン取得→オフライン新Worker・ページ再読込|
|データ|ラベル全件と親子辺全件の一致|HTML・URL・制御文字を実行しない|絵文字・長いラベル、最大ノード|クリア後に本文・旧SVGが復活しない|
|UI|スクロール・応答性を維持|エラー後も操作可能|最大図の有限寸法|描画中のクリア・再試行|

## 代替案と選定

- 同一オリジン iframe: キャッシュ到達性は改善し得るが、メインスレッドとの実行分離を保証できず中断問題を残すため選定しない。
- 汎用 Mermaid DOM レンダラーのWorker移植: DOM依存を模倣する範囲が大きく、文字品質・安全性の検証範囲が増えるため今回選定しない。
- JSON木専用の独立レイアウトWorker + 制限したSVG構築: 採用する試作候補。Mermaid構文検証とエクスポートは保持し、表示座標計算を独自の木配置に置き換える。**Mermaid本来のレンダラーとは異なる表示方式であり、現行要件への無条件適合とは判定しない。**

前提: 合成データのみ、専用ポート4187、ブラウザーごとの新規コンテキスト。Chrome/Edge/Firefox/WebKitを順次実行する。オフライン試験は静的資材取得後と未取得時を区別する。ケースは通常描画、強制長時間処理、中断後再試行、世代交代、温キャッシュ再描画・再読込、冷キャッシュ失敗、最大図、保存・通信監査。ログは状態・件数・時間・一致判定のみとする。

E2E範囲はG-04対象ケースのクロスブラウザー。既存G-01～G-03全件は変更範囲外のため実施しない。実機Safari/iOS、画面読み上げ、OSメモリ圧は別途必要。

## 残件の切り分け観点（今回のケース作成前に整理）

|分類|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|期限内ready採用・新Workerで回復|readyなし・期限後ready拒否|readyが期限直前／直後|初期化→中断→再試行、クリア後の旧通知|
|非機能|絶対期限と時計の比較|長時間タイマーの配送遅延・SW起動失敗|15秒、5秒、短周期監視|前面／非表示・オンライン／オフライン|
|データ|キャッシュに静的資材とHTMLが存在|キャッシュ欠落・不正な応答属性|同じHTMLの元応答／再構築応答|再読込で入力を復活・永続化しない|
|UI|親UI応答継続・再読込後に初期化|無警告の待機・誤成功表示を防ぐ|期限付近の非同期競合|失敗→明示操作のみで回復|

原因仮説: Firefoxは長時間タイマー／イベント配送・時計・背景状態を対照測定する。WebKitはSWの制御有無、fetchイベント到達、Cache一致、応答形式、オフライン模擬方式を分ける。単独と通しの双方で証跡を取得し、再現しない仮説は断定しない。

新規コンテキスト・既存の合成fixture・同一ビルドを前提に最小再現→改善→対象限定追試→4ブラウザーのG-04対象ケースを順次実施する。本体のソース・SW・依存と要件／設計本文は変更しない。タイムアウトの延長と試験許容値の緩和では解消扱いにしない。
