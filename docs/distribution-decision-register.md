# 配布条件の判断表と完成までの作業

2026-11-05、PR #29 マージ後の main `17aa0fe254214fbec327f2870098c7fc1e8e329d` を基点とする。これは判断材料と推奨案であり、配布条件の充足・配布許可・法的見解の確定ではない。実機はユーザー別途、macOS/iOS は対象外。アーカイブの公開・添付、デプロイは行わない。

## 状態の読み方と検証観点

「確認済み」は示した対象・時点での事実、「追加作業」は判断前後にこちらで実施できる作業、「判断待ち」は責任者による選択または必要な専門家確認が残る状態を意味する。同じ項目に複数の状態がありうる。未証明のまま了承しても、適用される条件が免除されるわけではない。

最優先は、別版の原文・ソースを対応済みとして告知すること、欠落を見逃して配布可能と表示すること。機能は対象と取得先、非機能は容量・可用性、データは版・hash・原文/NOTICE・除外、UI/報告は案内先と判断状態を確認する。正常、欠落・取得不能、空/複数原文、版の切替を区別する。ここでの整理は静的証拠の評価であり、実配信・実機テストの結果ではない。

## 推奨する判断順序と次の動作

1. **版と配布方法:** 現行依存を前提とする単一の配布候補を決める。配布先・ソース提供先の具体名、管理者、保持・復旧方法は未決定。仮の URL を利用者向け画面へ置かない。
2. **原文・告知・ソース:** 上表の ELK、WASM、DOMPurify、NOTICE を対象に、適用関係と必要な証拠を個別に確認する。ELK checkout や WASM の一意な再ビルドは無条件の一律要件としないが、必要な対応ソースや条件を確認できないまま「配布可能」ともしない。判断を「確認済み」「不足のため保留」「適用外の根拠」に分ける。
3. **整備:** 決定された提供範囲に不足する資料・案内・実装をこちらで準備し、版・hash と取得不能時の動作をレビューする。ローカル ZIP は候補であり、自動的に公開対象にはしない。
4. **受入:** Windows の実機手順はユーザーが別途実施。固定版について実配信環境で内容、原文、提供先、更新・オフライン・回復を確認する。公開またはアーカイブ添付が必要な検証は、具体的な対象・場所・公開範囲の承認後に実施する。
5. **最終判断:** 成否・未実施・残リスク、判断者と根拠を記録し、公開可否を決める。マージやデプロイの指示は別に受ける。
