# Windows クリーンインストール・配布物再生成の検証

2026-11-05、PR #27 マージ後の main `1dfafd115a3632963a029027bf7cabd9a59c8e36` を対象に、既存 `node_modules` とは別の空ディレクトリーに固定 commit を展開して実施した。Windows、Node.js `v24.22.1`、npm `11.19.1`。対象 lock の SHA-256 は `ca28ec7d0ade3ff0a349dad2f91f661f7b05d841c420a0bba3d30681002d771c`。配布承認ではない。

## 観点と前提

最優先は、古い依存や混在した資産のまま再現できたと誤認すること（重大）。比較基準は PR #26 後のローカルビルドで、公開物ではない。新ディレクトリーには commit の追跡ファイルだけを展開し、既存の `node_modules` や `dist` はコピーしない。npm cache と registry は利用する。

|観点|正常|異常|境界|状態遷移|
|---|---|---|---|---|
|機能|固定 lock から導入・build・検査|取得不能、テスト停止、build 失敗|初回の空ディレクトリー|既存依存なし→導入→build|
|非機能|Windows で必要なツールが動く|cache 不足・プロセス起動制限|ワーカー数・OS 差|オフライン失敗→新規領域で通常取得|
|データ|全成果物のパス・hash 一致|欠落・追加・別 bytes|manifest と SW の自己参照境界|既存候補と再生成候補を分離して照合|
|UI/報告|成功・未確認・環境差を分離|誤った完全再現の主張|ブラウザーと実機の対象外|候補→配布判断を自動的に行わない|

## 実施と結果

1. 別の空ディレクトリーに Git 追跡ファイルを展開し、lock hash の一致を確認した。`npm ci --offline --no-audit --no-fund` は必要パッケージがキャッシュになく `ENOTCACHED` で失敗。終了時に一部ディレクトリーの `EPERM` 警告も出た。通常ユーザー側キャッシュでも不足したため、失敗した場所を再利用せず、もう一つの空ディレクトリーで通常の `npm ci --no-audit --no-fund` を実行し、345 パッケージの導入が成功した。このコマンドでは脆弱性監査は実施していない。
2. 同環境で `npm run build`、`npm run check:dist`、`npm run check:docs` が成功。文書は67件・ローカルリンク278件。manifest の SHA-256 は `255ad9a0570b21f1dd8d183c3a34a73bfcb843bec23019086dc74efd26ff7b85`、世代 ID は `c86c92d953f97dd762782d79`。SW の SHA-256 は `ee05a73bad634fdf4a8465d9a253ffcec7eaf7ff7f742fb968488ad7a306dc9e`。
3. 既存のローカル `dist` と新規生成 `dist` を相対パスと SHA-256 で全件比較。双方444ファイル、片側のみ0件、hash 不一致0件。比較には manifest と SW を含む。これは今回の2つのローカル生成物の一致で、上流 WASM や ELK の再ビルドではない。
4. 当初 `npm run check` を Vitest 開始後に中断した。対象1ファイルを切り分けた後、`npm run test:unit -- --maxWorkers=1 --no-file-parallelism` は21ファイル・121テスト、`npm run test:pwa` は11件成功した。**訂正:** 当初「既定並列」と表現したが、既定設定も単一ワーカーである。中断後に残ったログには121件成功が記録されていたものの、一括コマンド全体の終了コードは得ていなかった。下記追補で既定コマンドを再実行した。

## 限界・残件

Windows のこの Node/npm・キャッシュ・ネットワーク条件での再生成結果であり、他の端末・OS・クリーンネットワークや今後の registry 可用性へ一般化しない。E2E はインストールと静的な再生成の検証が目的で製品変更もないためローカル未実施。CI のブラウザー検証は別の証拠とし、実機・配信先・オフライン更新は未確認。macOS/iOS は対象外。

ELK の実 checkout、WASM 実リンク graph、PDFium 候補の除外1件、告知・対応ソース・提供先の判断は引き続き[配布判断表](distribution-decision-matrix.md)のとおり未解決。アーカイブ公開・添付、デプロイは行っていない。

## PR #28 後の追補: 既定設定の再確認と訂正

2026-11-05。PR #28 をマージ後、前回の固定 source `1dfafd115a3632963a029027bf7cabd9a59c8e36` と同じクリーン導入済み環境を再利用した。main `fc1b01bcd20f4f51690d54b864d1fb3f46b5c0d8` の追加は報告書・backlog・デプロイ抑止設定で、テスト・ビルド入力の変更はない。再インストールや別 OS での検証ではない。

最優先は、未完了を失敗と断定することや、テストの成功を配布全体の成功と誤認すること。機能は既定コマンドの終了、非機能は結果表示までの時間、データはテスト件数と終了コード、UI/報告は中断と成功の区別を確認する。正常・中断・結果待機時間の境界・中断後から再実行までの状態を分けて扱う。

- 対象 source の `vite.config.ts` は `maxWorkers: 1`、`fileParallelism: false`。前回の「既定並列」「単一ワーカーに変更して成功」という含意は誤りであり、設定差による原因とは言えない。
- 前回の通常環境の中断ログに、Vitest 21ファイル・121件成功と実行時間44.39秒が記録され、続いて PWA 11件の成功と build 開始も記録されていた。中断後も子処理の出力が続いたため、親側の中断だけから全処理が停止したと判断できない。中断時の一括終了コードは得ていない。
- 同じ環境で CLI オプションを追加せず `npm run check` を再実行し、終了コード0。Vitest 21ファイル・121件成功、PWA 11件成功、build・`check:dist` 成功。Vitest は結果表示まで64.99秒だった。結果がまとまって表示される間に当初中断した可能性はあるが、当時の状態の原因を断定しない。
- 再発防止として、出力がないだけで停止と判断せず、実行中プロセスとログを確認し、終了コードを取得する。中断時は子処理の終了も確認し、ログ上の個別成功と一括コマンド全体の終了を区別する。タイムアウト延長だけを原因解消として扱わない。

今回の変更は記録の訂正のみで、ローカル E2E・実配信・実機は未実施。ブラウザー・OS・負荷の異なる条件での成功や、上流生成物・配布条件の証明にはならない。
