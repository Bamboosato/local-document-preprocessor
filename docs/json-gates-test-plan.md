# JSON v0.2（追補1）技術検証計画

対象: 要件定義書・画面設計書v0.2（追補1）、基準`b0aa784`。

## 最優先で防ぐ不具合

致命: 数値・キー・子孫の無警告欠落、範囲違い、文書間混入、入力の実行・外部送信・永続化。重大: 回復不能、キャンセル不能、UIフリーズ、誤った成功・出力許可。

## 検証の構成と前提

- `experiments/json-gates/`に独立した試作・固定依存・合成fixture・再実行手順を置く。productionの入力受付・Worker・画面には接続しない。
- G-01は自動検査、G-02～04は実ブラウザ上の専用ハーネスで検証する。全ブラウザ・実機への保証はしない。
- 外部サービス・実文書を使わない。証跡はfixture ID、集計値、状態・時間・世代・検査結果に限定する。
- 初期状態を作り直し、ブラウザごとに逐次実行する。同一実機でスクリプトを並列実行しない。
- まずゲート対象だけを実行する。production共通経路を変更しないため既存全E2Eは既定で実行しない。
- 長時間描画の合成負荷は時間を有限にし、親タイマーが実際に動いた時刻を外部の自動化プロセスから測る。iframe採用だけを独立中断の証明にしない。

## 合否と制約

G-01は入力・生成・AST／plain textの一致、G-02は1解析セット・回復・旧応答排除、G-03は到達性・選択不変・フォーカス、G-04は安全な表示と実際の中断を必須とする。部分検査だけの成功をゲート全体の通過としない。

Chrome／Edgeは利用可能な実ブラウザを確認する。Playwright WebKitはSafari／iPhone実機の代替証明にしない。手元にないmacOS Safari／iPhone、実スクリーンリーダー、実端末メモリ・PWA更新は未確認として記録する。

失敗は実装問題／データ問題／環境問題／テスト観点不足に分類する。再現できた場合のみ原因を判定し、安全性・完全性の基準を無断で緩めず、不成立なら本体統合を止める。
