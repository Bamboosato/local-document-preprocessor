## 判定

**独立Worker方式で、前回の「描画中断不能」「取得済み資材によるオフライン再描画失敗」は、Windows上の4ブラウザー検証で解消した。本体には統合していない。**

ただしG-04全体の通過とは判定しない。Firefoxの初期化15秒期限の精度、WebKitのオフラインページ再読込、実Safari／PWA確認が残る。独自SVG配置への表示方式変更についても、要件・設計への採用判断が必要である。

## 選定した方式

1. 従来と同じ固定版Mermaid `12.2.0`・厳格設定で、別Workerがソースを構文検証する。未検証・検証失敗の出力は禁止する。
2. 生成したJSON木モデルと検証対象Mermaidソースの一致を検査する。文書由来の文字列をコードとして実行しない。
3. DOMを使わない専用Workerが最大200ノードの配置を計算する。初期化済みWorkerに渡してから5秒を計測し、超過時はWorkerを実際に終了する。
4. 画面側は固定SVG要素・数値座標・textContentで表示する。10ノード単位で処理を譲り、クリア・世代交代後の途中結果は採用しない。失敗時は検証済みソースを明示表示し、出力を保持する。
5. 静的資材は試作専用Cache Storageから読み出す。自己完結した静的Workerコードを起動し、文書・生成したMermaidソースはpostMessageだけで渡す。入力・結果をURLやキャッシュへ入れない。

Mermaidの標準レイアウトをそのままWorkerへ移植したものではない。JSON木専用の図表示であり、エクスポートするMarkdown／plain textのMermaidソースは維持する。図の配置・折返しは外部Mermaid閲覧環境と異なる。拡大縮小・操作UIの製品実装は今回の対象外。

同一オリジンiframeは実行分離の問題を残すため不採用。汎用DOM環境をWorker内に模倣する方式は、安全性・文字品質の検証範囲を拡大するため今回採用しなかった。

## WebKitのオフライン起動の切り分け

アプリを使用しない小さな静的Workerによる最小再現でも、WebKitはオンラインのBlob Worker起動が成功し、オフライン設定では失敗した。同じ条件のdata URL Workerは成功した。Chrome／Edge／Firefoxは両形式とも成功した。これは今回のPlaywright実行環境での観測であり、実Safari全般の原因や挙動を断定するものではない。

全環境をdata URL起動へ一律変更した案は、大きな構文検証コードをChromeで起動できず不採用とした。現在は小さな静的コードでBlob起動可否を確認し、使用可能ならBlob、使用不可ならdata URLを使う。ブラウザー名による分岐ではない。Blob URLは処理終了・中断・クリアで破棄する。

資材一覧による先行取得だけではWebKitの起動失敗を解消できなかった。最終候補では、静的キャッシュの直接読出しと自己完結コードの起動まで実施し、オフライン再描画・新コンテキストでの再検証が成功した。ページ再読込は別の失敗として残している。

## 未解消事項と採用前の条件

- **重大: 初期化期限の精度。** Chromeは15,006.2ms、Edgeは15,009.2ms、WebKitは15,006ms。Firefoxは通し実行で15,316msとなり、試験の15,300ms未満を満たさなかった。前面表示を明示した単独再実行でも15,672ms、証跡強化後の追試でも15,649msで失敗し、document.visibilityStateはvisibleだった。タイマー配送や実行環境の揺れは仮説であり、背景タブだけを原因と断定できない。終了自体・検証済み出力保持・新Workerでの回復は確認したが、期限精度は合格にしない。次は独立した期限監視等を比較し、計測証跡付きで原因を絞る。単なる待機時間延長は提案しない。
- **重大: WebKitのオフラインページ再読込。** 再描画は成功するが、ALT-11はナビゲーション段階で失敗する。SW／ページ遷移／自動化環境の切り分けとSafari実機確認が必要。取得済み資材だけでPWA全体が起動可能とする証明にはならない。
- **方式差分。** 図表示は独自SVG配置になる。仕様採用時は隔離・CSPの設計も合わせて更新する必要がある。静的コード用のBlob／data Workerを許すCSPの製品検証は未実施。本体のCSP・Worker・SWは変更していない。
- **資材量・更新設計。** 現ビルドの先行取得対象は120ファイル、10,874,527 bytes（約10.4 MiB）にHTML・資材一覧を加えたもの。比較用資材も含む。必要な資材だけへの分離、世代更新・旧キャッシュ破棄・ストレージ拒否・容量不足の扱いは製品向けに未実装。再現時は新規コンテキストを使用する。
- **未実施環境。** 実macOS／iPhone Safari、インストール済みPWA、低メモリ・OS強制終了、バックグラウンド復帰、実ページズーム・読み上げ・タッチ操作。デスクトップの成功を全対応環境へ一般化しない。

優先して防ぐ致命的不具合は、本文の外部送信・永続化、別文書混入、不正SVGの実行、未検証結果の出力である。今回の対象fixtureでは検出していないが、製品全体の安全性保証ではない。

## 成果物・証跡・検証範囲

- 試作は `experiments/json-gates/` 内。`diagram-worker-host.mjs`、`layout-worker.mjs`、`alternative-sw.js`、`alternative-check.mjs`、`offline-worker-probe.mjs` を追加した。共通生成結果に親子モデルを追加し、専用ハッシュで方式を切り替える。従来iframe候補と初回証跡は保存した。
- `evidence/alternative-<engine>.json` が通し実行。`*-diagnostic.json` 等は方式比較・失敗切り分け用、`*-foreground.json` と `*-failures.json` は対象限定の追試。本文・ラベル・実行URLをログへ出さず、件数・時間・状態・照合判定だけを保存する。生成証跡とdistはGit管理対象外。
- E2E範囲は**G-04対象ケースのクロスブラウザー**。G-01～G-03全件、既存アプリ全E2E、production混在キュー・公開環境は今回実施しない。Workerバンドル形式を試作内で自己完結型に変更したため、初回iframe報告と同一ビルドによる比較ではない。
- 製品ソース、root依存定義、production SW、要件・画面設計書は変更していない。公開・コミット・PR・デプロイは行っていない。
- 共通生成結果への図モデル追加に対し、既存の厳密解析・生成・境界値検査21件を再実行し、21件成功・失敗0を確認した。試作ビルドも成功した。これはブラウザーの未達2件を相殺するものではない。
- 文書検査は24文書・50ローカルリンクで問題0。試作サーバーは検証後に停止した。

**今回の推奨は、このWorker方式を次の検証候補として残し、本体統合は保留すること。前回の中断・オフライン再描画の障害は改善したが、残る期限精度とPWA／実Safariの確認を通過させてから採用を判断する。**
