> 2026-10-30: 以下は旧独自SVG試作の手順。[標準Mermaid採用設計](json-standard-mermaid-design.md)へ変更したため、図内ズーム/全体表示や旧PWA手順を新方式の必須受入としてそのまま使わない。ブラウザー実200%倍率・読み上げ・タッチ・復帰はユーザー別途。新方式のPWAパッケージは未提供であり、旧成功の転用はしない。

2026-10-27。**実測結果ではない。全項目はNOT_RUN。** 本体統合、macOS/iOS、マージ、デプロイは対象外。[過去の包括手順](json-device-validation-runbook.md)から今回のWindows向け操作と前提を分離した。

## 確認できる範囲と前提

対象はPR #17の`experiments/json-gates`の共存試作。ChromeとEdgeを別々に、一台で一つずつ操作する。製品のJSON設定dialog、混在キューUI、コピー/DLボタンは未接続。現試作にはPWAのmanifest/インストール用パッケージもない。以下のWR-04は対応パッケージが提供されるまでBLOCKED_PRECONDITIONで止める。既存製品PWAの確認をJSON対応PWAの成功に読み替えない。

Windows、Node.js 24、インストール済みChromeまたはEdgeを使用する。既存の未保存作業を先に保存する。記録するのはcommit、OS/RAM、ブラウザー版、読み上げソフト版、使用ポインター、空き容量、電源状態、fixture ID、状態、実測値、再現回数。本文、Pointer、個人のファイル名、プロフィールの絶対パスは共有しない。

ソースをPRの固定headへ揃え、対象commitを記録してから以下を順に実行する。PR更新でheadが変わったら以前の結果と分ける。コマンドは検証専用の作業コピーで実行する。

未コミット作業がある場合は先に保護し、強制切替はしない。PR #17のブランチへ揃える場合は`git fetch origin`、`git switch codex/json-integration-readiness`、`git pull --ff-only`を順に行い、その後はケース実行中にソースを更新しない。

```powershell
git rev-parse HEAD
npm ci
Push-Location experiments/json-gates
npm ci --ignore-scripts
npm run build:integration
npm run check:integration
node manual-session.mjs chrome ready
```

初期化と合成fixtureの表示までを補助スクリプトが行う。専用4190のpreviewと、既存プロファイルとは別の一時ブラウザーcontextを使用し、本文をStorageへ保存しない。初期化は自動操作であり、読み上げ/倍率/操作性の合格を記録するものではない。`prepared: true`でも実機判定はNOT_RUNのまま。

表示できたら、以降はユーザーがブラウザーを直接操作する。終了は専用ブラウザーを閉じるか、起動したPowerShellでCtrl+C。その後`Pop-Location`する。4190が使用中なら既存プロセスを強制終了せず、先の検証を終了する。接続不能時は別途再現し、保護設定・プロキシ・ファイアウォールを無効化して回避しない。

Edgeは上の最終行を`node manual-session.mjs edge ready`へ変える。警告状態は`chrome invalid`、図だけのタイムアウトは`chrome display-failure`、fixtureを投入しない空画面は`chrome empty`を指定する。各シナリオは前の専用ブラウザーを終了してから新規起動する。display-failureは検証済み本文を保持したままの5秒描画タイムアウトを作り、再試行は通常モードに戻してある。これらは合成の故障注入で、実メモリ不足を再現した証拠ではない。

## ケースより先に確認する観点

|観点|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|図/ソース切替・明示再試行|検証失敗、配置失敗|200ノード/199辺|表示→警告→回復、終了→再起動|
|非機能|実ブラウザーと読み上げ・応答性|復帰、容量/メモリ不足|実200%・負荷を一段ずつ|オンライン/オフライン、更新待機/activate|
|データ|合成fixtureの全量を保持|古い結果・他セッション混入|根と末尾に到達|再試行で本文不変、終了後に入力復元なし|
|UI|名称・状態通知・Tab/タッチ操作|読めない警告、フォーカス消失|図倍率上下限、狭い表示領域|図↔ソース、100%へ戻す、フォーカス復帰|

まず防ぐべき致命的不具合は、未検証本文の表示/出力、文字・辺の無警告欠落、別結果混入、入力の保存・送信。主要操作不能・UI停止・回復不能は重大。単なる見た目の差だけを致命/重大としない。

## ケースと期待結果

|ID|準備と操作（意図）|期待値・証跡・停止条件|
|---|---|---|
|WR-01 読み上げ|利用中のNVDA等を有効にし、`ready`を起動。Tab/Shift+Tabで図/ソース・倍率・表示領域を移動し、Enter/Spaceで操作。`invalid`と`display-failure`も新規起動して読む|操作名、現在の切替状態、図の説明、検証失敗と表示失敗の違いが伝わる。readonlyソースは読めて変更不可。図titleの存在だけでは合格にしない。意図しないフォーカス消失/閉じ込め、警告が読めない場合は記録して停止。製品設定dialogの読み上げは未実装として別記|
|WR-02 実200%ズーム|`ready`を起動。ブラウザーのメニューのズームで200%にし、メニュー上の値を確認。図とソース、図の拡大/縮小/100%/全体表示を操作。根と末尾にスクロールで到達する|ブラウザー200%と図内倍率は別に記録。CSS拡大/viewport変更では代用しない。操作名/警告/ボタンが重ならず到達可能。全体表示の小さいラベルは図拡大またはソースで読めること。200%のメニューと対象領域を必要に応じてマスク画像で残す。終了前にブラウザー倍率を100%へ戻す|
|WR-03 実タッチ（対応機がある場合のみ）|`ready`と`display-failure`を別々に起動。画面への直接タッチで切替、倍率、領域スクロール、再試行|マウス/タッチエミュレーションと区別。誤操作やスクロール不能がなく、再試行で警告から回復しソースを維持。非対応機はNOT_APPLICABLE（対応未確認）と記録し、合格に数えない|
|WR-04 インストール済みPWA|**現在は前提未成立。** 固定commitに対応するインストール可能な独立パッケージと、同一localhostオリジンで切り替える2世代、切替/復旧手順が提供された場合だけ開始|インストール→2つの旧画面に合成結果→新版提供→旧画面を一つずつ終了→再起動を確認。作業中の強制置換なし、全旧画面終了後だけ新版へ。自分の旧Cacheのみ削除、無関係データ維持。オフラインで新WASM/Workerが動作し、入力は復元しない。配信/デプロイが必要なら今回の対象外として止める|
|WR-05 終了・スリープ・復帰|`ready`と`display-failure`で、まず表示済み/失敗済み状態を記録してWindowsを通常操作でスリープ→復帰。同じ画面を再読込して空画面を確認。最後に終了→`chrome empty`で新規起動|復帰後に操作でき、同contextの再読込で入力は復元されない。補助スクリプトは再読込時にfixtureを再投入しない。新規起動は別contextのため同一プロフィールの永続化検査の代用にはしない。処理中スリープの期限検査は専用fixture未提供として未実施。OS強制終了を意図的に起こさない|
|WR-06 実容量・メモリ圧|**専用検証環境と安全な負荷/復旧計画を別途用意した場合のみ。** 事前に空き容量/RAM、停止閾値と回復方法を記録。一度に一条件、一段ずつ負荷を上げる|普段使いのシステムディスクを埋めない。未保存作業へ影響、OS全体の応答悪化、安全余裕への到達時は直ちに負荷を止める。負荷による例外を成功表示せず、旧結果の無警告欠落なし、負荷解除後に明示操作で回復。PWA更新負荷はWR-04の前提も必要。故障注入のみは実容量/OS圧の合格にしない|

数値の合否閾値が未合意の性能観点は、勝手に合格基準を作らず実測値と条件を残す。マシンが操作不能になった場合は同じ負荷を再投入しない。安全な範囲で再現できる場合だけ、初期状態へ戻して単独/通しの差を確認する。

## 記録・復旧と提出

[記録テンプレート](json-windows-manual-results-template.md)にケースごとの初期状態、操作順、期待と実際、成否、再現回数、環境、証跡IDを記入する。NOT_RUN、BLOCKED_PRECONDITION、NOT_APPLICABLEをPASSと区別する。全件を実施する必要はなく、対象機と前提に応じて実施範囲/選定理由/未実施範囲を残す。

失敗は「テスト観点不足/データ問題/環境問題/実装問題/原因未確定」で仮説を記録する。原文・PII・無加工コンソール/HARは添付しない。証跡はID・状態・版・寸法・時間と必要なマスク画像に限定する。専用ウィンドウとpreviewを終了し、倍率と負荷を戻す。他オリジンのStorageやユーザープロファイルは消さない。

今回こちらで行うのは手順/補助スクリプトの整備までで、実機確認はユーザーが別途行う。製品dialog/キュー/出力、製品PWAの受入は本体統合保留の間は未実施のままとする。
