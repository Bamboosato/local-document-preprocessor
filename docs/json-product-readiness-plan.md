# JSON製品採用前の追加検証計画

仕様は[要件v0.2追補1](local-document-preprocessor-json-requirements-v0.2.md)・[画面設計v0.2追補1](local-document-preprocessor-json-screen-design-v0.2.md)。過去の[結果](json-g04-followup-validation.md)を今回の成功件数へ加算しない。

## ケースより先に固定する観点

最優先は致命的な未検証本文公開、文字欠落、文書間混入、送信・永続化。重大リスクは中断不能、更新での起動不能、未取得資産での誤成功。

|観点|正常系|異常系|境界値|状態遷移|
|---|---|---|---|---|
|機能|静的URLの検証・配置Worker、全ラベルと辺の一致|不正ソース、資産欠落、表示だけの失敗|200ノード・199辺、5秒／15秒|未検証→検証済み→描画、取消→新世代|
|非機能|CSP self、静的資産だけの最小ビルド|保存拒否・容量不足・取得失敗|取得済み／未取得、世代一致／不一致|更新待機→旧タブ終了→activate→旧資産削除|
|データ|数値字句・制御文字・Pointer保持|入力由来HTML・リンク、キャッシュ対象外要求|最大入力50 MiBと保持1セット|入力A完了→PDF B取消→A/C再設定、クリア後の旧応答|
|UI|表示状態と出力許可の分離、非表示対象への到達|未検証からの図再試行拒否|300行・64px、320px・実200%ズーム|適合→不適合→適合、オンライン復帰時の非自動実行|

## 初期状態・実行順序

合成fixture専用。rootと試作のSDK・依存実体を別々に記録する。既存4187と追加4188は専用ポート。新規コンテキストで開始し、同じ実機ではビルド・計測・ブラウザーを一つずつ実行する。本文、キー、Pointer、ファイル名、実行URLをログへ出さず、ID・状態・時間・件数・一致判定だけを残す。

## 追加ケース

全ケースの共通前提は上記の新規コンテキストと固定ビルド。PR系は独立ページ上の静的Worker方式であり、既存Blob/data方式とは別候補。

|ID / fixture|意図・防ぐ不具合|手順と期待値|必要環境|
|---|---|---|---|
|PR-01 / hostile-tree|安全性と文字・辺の完全性|危険文字列を含む生成結果を検証・描画。全ラベル・全辺一致、能動要素なし、selfの静的Workerだけ|4ブラウザー、CSP付きHTTP|
|PR-02 / max-tree|最大図で省略しない|200ノード・199辺を描画し全量比較|同上|
|PR-03 / busy-layout|中断・回復で未検証出力を公開しない|6500ms負荷を5秒で終了、親UI応答、検証済み本文を保持して明示再試行|同上|
|PR-04 / invalid-source|検証失敗から出力しない|不正文法・モデル不一致を拒否し図再試行不可|同上|
|PR-05 / warm-assets|CSP selfで取得済みオフライン起動が成立するか|SW制御・資産取得完了後にオフライン再読込、新しい検証・配置Workerで描画。未達も記録し迂回しない|同上、Playwright WebKitは実Safariと区別|
|PR-06 / cold-assets|未取得資産で成功を偽装しない|SWなしでWorker要求を遮断、未検証出力停止。復帰のみでは再実行せず明示再変換で回復|同上|
|PR-07 / no-ready|初期化期限と旧世代の排除|readyなしの静的Workerを15秒で破棄、クリア・再試行で古い図が戻らない|同上|
|PR-08 / static-only|送信・永続化を防ぐ|全要求・Cacheキー・Web Storage・IndexedDB・Worker schemeを検査。外部HTTP要求0、本文保存なし|同上|
|SW-01 / two-generations|更新時に別用途キャッシュを消さない|install完了後のactivateで同prefix旧世代だけ削除|NodeのSWイベント模擬。実PWAの代用不可|
|SW-02 / quota-denied|更新失敗で旧版まで壊さない|addAll失敗で新世代キャッシュを除去し旧世代を保持、installを失敗にする|同上|
|SW-03 / storage-denied|保存拒否を成功にしない|caches.open失敗をinstall失敗として伝える|同上|
|SW-04 / forbidden-request|入力・API・クエリの保存防止|非GET、クエリ、外部、非manifest URLをSWが処理しない|同上|
|SW-05 / denied-fetch|保存拒否でオンライン経路を止めない|Cache読出し拒否時は許可された静的要求だけをnetworkへ渡す。追加保存しない|同上|
|PR-B01 / built-assets|HTML欠落による再読込不能を防ぐ|生成manifestと配布HTML・JS全量の集合一致、両Workerと世代を照合|Node、追加候補のビルド後|
|G03-R01 / target-return-race|旧応答で確定を有効化しない|実Workerの旧正常生成応答を保留し、summary→resultsへ操作。旧応答を解放・再送し、現詳細・生成が揃うまで決定不可。スタイル保持と確定時だけ旧結果破棄|既存4187試作、4ブラウザー。逐次キューのため詳細要求そのものの逆転は作れず、古い応答の遅着・重複を検査|
|G02-M01 / peak-components|前回のメモリ検査で含めなかった最大入力・完了結果・図資産の保持を確認|Chromeで基準→50 MiB入力→解析追出しと入力置換→20件の約1 MiB本文の完了結果→最大図→結果解放を逐次CDP計測。GC前後を分ける。真のピーク／プロセス総量／実機保証としない|既存4187のWorker候補。ほかの検証を同時実行しない|
|ENV-viewport / blank-page|Firefoxのサイズ変更待ちをアプリから分離|アプリなし固定HTMLで1280→320への変更を10秒以内に完了できるか確認し、最初から320のcontext作成と比較。失敗もそのまま記録|Chrome/Firefoxを逐次。SW・Cache・JSON・外部通信なし|

## 既存資産の再利用と範囲選定

既存core/deadline単体検査とビルドを再現する。既存図コントローラーの起動経路へ拡張する場合はALT-01～12のクロスブラウザーで回帰する。G-02/G-03は現在の環境を再確認する対象ケースを選び、最大入力・混在回復・適合対象への復帰・非表示ラジオ・レイアウトを含める。製品共通経路は変えないが、現行CIの範囲選択ではexperiments変更が未分類として全件に選ばれるため、製品Chromium E2Eも1 workerで全件を実施する。実Safari、インストール済みPWA、読み上げ・タッチ・実ズーム・OSメモリ圧は別の手動手順へ残す。

失敗時はケースID、段階、SDK/ブラウザー版、状態、時間と再現手順を残す。環境問題・実装問題・データ問題・観点不足を分ける。許容値やCSPを緩めて成功扱いにしない。
